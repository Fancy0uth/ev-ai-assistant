## Root cause and minimal repair

`webpDimensions()` structurally accepted exact-size RIFF objects whose `VP8 ` chunk contained only its 10-byte frame header or whose `VP8L` chunk contained only its 5-byte header. Those headers supply 1×1 dimensions, but neither contains decodable compressed pixels. The synchronous metadata reader therefore allowed upload to reach artifact write and SQLite insert.

`readImageMetadata()` is now async. It first retains all existing signature, RIFF/chunk-size, padding, animation, VP8X feature/canvas, 12,000-dimension and 40M-pixel validation. Only after those checks, only for `image/webp`, it invokes local `sharp(..., { failOn: 'error', limitInputPixels: 40_000_000 }).stats()`. `stats()` is a pixel-derived operation; it reads decoded pixels without producing a raw image output buffer. Any decoder failure is caught and mapped to the existing `IMAGE_DIMENSIONS_INVALID`, which the unique production caller maps to 422 before dedupe lookup, artifact write, DB insert, or any Vision path. Decoder errors, paths, and image bytes are not logged.

PNG/JPEG behavior, the 5,000,000-byte input limit, 12,000 dimension limit, 40M pixel limit, animation rejection, and all existing WebP structural checks remain unchanged.
