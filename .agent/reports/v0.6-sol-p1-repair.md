## Sol escalation conclusion: stale lease terminalization

This was the single Sol-authorized Terra point repair. Production scope was limited to `capability-run-repository.ts`; no service, adapter, provider policy, interface, schema, migration, version, or immutable review change was made.

### Root cause

- The stale sweep set `reserved_calls = actual_calls`. A claimed call with `reserved_calls=1` and `actual_calls=0` therefore became a zero-cost failure and released Owner/date/capability quota.
- The sweep updated only `external_capability_runs`; matching Course Import, Public Search, and Learning rows remained indefinitely in `EXTRACTING`, `SEARCHING`, or `GENERATING`.

### RED

- `npm test --workspace @ev/core -- tests/v0.6-capability-gate.test.ts -t "conservatively charges expired reservations"` — exit 1; expected 20 stale rows at 1/1 but observed zero.
- `npm test --workspace @ev/core -- tests/course-import.test.ts -t "atomically recovers an expired Vision extraction"` — exit 1; Course Import remained `EXTRACTING`, version 2, with no stale failure.
- `npm test --workspace @ev/core -- tests/learning.test.ts -t "atomically recovers expired Search and Learning runs"` — exit 1; the business-row rollback trigger was not reached because the sweep never updated `learning_runs`.

### GREEN

- `sweepExpired()` now runs as one SQLite IMMEDIATE transaction. It first selects the exact expired RUNNING capability rows, charges `max(actual_calls, reserved_calls)`, and updates each capability row by id/owner/still-expired lease.
- In the same transaction it updates only the matching owner/resource/capability-run business row still in its processing state: Course Import `EXTRACTING`, Search `SEARCHING`, or Learning `GENERATING` → `FAILED/CAPABILITY_EXECUTION_STALE`.
- A forced Learning business-update abort rolls back both capability rows and the already visited Search row; after removing the trigger, one sweep terminalizes both. Existing terminal business rows are unchanged, no Learning Proposal is created, and Provider call counters do not change.
- Twenty stale reservations settle to 1/1/NONE and continue to reject the same-day 21st claim. Other Owner/capability/date claims succeed. An explicitly completed zero-call failure remains 0/0/NONE after later sweeps.
