## 交付内容

- `/today` 首屏先展示时间块、具体行动、恢复状态和每日计划入口；任务/日程跳转到对应工作区。
- `/daily-plan` 的每份草案可按需展开“查看本次上下文与校验”，显示最小 Context 类别、草案和当前日程版本，以及每项本地验证结果；不会显示 API Key。
- Core 以 `Asia/Shanghai` 的下一次 07:00 一次性 timer 触发 Daily Plan。若进程错过该时间，Owner 当天第一次访问 `/v1/today` 时仅补偿一次。
- 自动计划只有在 DeepSeek 凭据已配置且当天没有既有 Daily Plan Run 时才生成；数据库迁移 16 对同一 Owner/日期的两种自动触发方式设置唯一约束。
- 生成过程只创建待审核 Proposal。没有凭据、模型/网络失败、校验失败或自动触发均不会直接写入 Event；只有 Owner 采用草案项后才会写入时间轴。
- Today 真实显示 `GENERATING`、`FAILED` 或审核状态。结构化日志仅保存事件名、触发方式和已分类的失败码，回归测试证明不会记录任意 Provider 错误文本。

## 体验验收步骤

1. 使用新的 `EV_DATA_DIR` 启动 Core，再启动 Web；不要复用个人开发数据库。
2. 打开 `http://127.0.0.1:3000/setup`，自行创建唯一 Owner；本版本没有默认/预设账号或密码。
3. 在 `/today` 验证时间安排、具体行动和每日计划入口均可见；在手机 Safari 打开同一路径，确认没有横向滚动。
4. 在 `/settings/providers` 输入自己的 DeepSeek Key 并主动测试连接。未配置时不应出现虚构的 AI 输出。
5. 在 `/daily-plan` 生成草案，展开上下文说明；编辑、采用或拒绝单项。采用前日程如已变化，应看到 stale 提示而非静默覆盖。
6. 在 Core 持续运行且已配置 Provider 时，观察上海时间 07:00 的草案生成；停机错过后，在当天首次打开 `/today` 验证只补偿一次。两种自动路径都只产生待审核 Proposal。

## 已知限制与回滚

- P2：`dashboard.css` 仍是集中样式文件；功能切片优先保障行为，后续应按工作区拆分。
- P2：当前远程访问前还需要最小权限文件授权、私有 HTTPS、备份/恢复和观测设计。
- P3：课表 OCR/公开资料搜索、动作 RAG、自然语言营养、真实本地 Codex、长期自动记忆、多 Agent 协商、外部日历/手环、Docker 和原生 App 未进入本版本。
- 回滚代码可用常规 `git revert` 针对本分支的 v0.3 提交；SQLite 迁移为加法迁移，回滚代码不会删除已有 Daily Plan 数据。执行物理数据库降级前必须先备份 `app.sqlite`、`-wal` 和 `-shm`。
