## 本次交付

V3-06 为既有本地优先 Dashboard 增加了手动生成每日排程草案的后端能力。它是提案层，不是自动排程或自动执行层：

- POST /v1/daily-plans/generate 仅为已认证 Owner 生成一个 PENDING_REVIEW 草案。
- 草案生成前会读取固定事件、软时间块、待排时间请求和恢复等级，并将最小化的约束投影交给 Provider。
- DeepSeek 密钥只通过既有 Windows DPAPI 凭据桥接短暂使用；不会进入 API 响应、SQLite 草案、Provider 输入以外的持久化位置或日志。
- 模型输出必须经过 Zod 契约和本地时间规则校验。未知或重复请求、错误时长、超出 05:00–23:00、违反可用窗口、与硬性事件或其它草案重叠、累计超过 960 分钟均会被拒绝。
- 生成开始时记录 Owner 的日程版本，保存时在同一 SQLite 事务中再次比较。期间发生 Event、TimeRequest 或 RECOVERY Signal 变化时，草案运行会以 DAILY_PLAN_BASE_VERSION_STALE 失败，绝不会覆盖较新的日程。

## 验收操作

1. 启动现有 Core 与 Web 本地服务，完成唯一 Owner 的 Setup 或 Login。
2. 在 Provider 设置中保存 DeepSeek API 密钥；未配置时接口应返回 409 DAILY_PLAN_PROVIDER_NOT_CONFIGURED，而非伪造回复。
3. 为某日准备固定事件与至少一个待排时间请求。
4. 使用已认证会话调用：

~~~http
POST /v1/daily-plans/generate
Content-Type: application/json

{ "localDate": "2026-08-17" }
~~~

5. 成功时验证 201 和 { data: DailyPlanProposal }，且草案状态为 PENDING_REVIEW。
6. 验证生成不会修改 Event、TimeRequest、Signal 或 Task；本版本没有应用草案的端点。

## API 错误契约

| 条件 | HTTP | 代码 |
| --- | ---: | --- |
| 未认证（即使请求体非法） | 401 | AUTHENTICATION_REQUIRED |
| 请求体不是严格的 { localDate: YYYY-MM-DD } | 422 | VALIDATION_ERROR |
| Owner 未配置 DeepSeek | 409 | DAILY_PLAN_PROVIDER_NOT_CONFIGURED |
| Provider 传输或服务不可用 | 503 | DAILY_PLAN_PROVIDER_UNAVAILABLE |
| 模型内容无法解析或不符合契约 | 422 | DAILY_PLAN_MODEL_OUTPUT_INVALID |
| 本地日程验证失败 | 422 | DAILY_PLAN_VALIDATION_FAILED |
| 生成期间日程发生变化 | 409 | DAILY_PLAN_BASE_VERSION_STALE |
