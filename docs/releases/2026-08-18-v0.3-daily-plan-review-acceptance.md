## 本次验收范围

V3-07 验证的是 Owner 主动确认的闭环，不是自动排程：

- 在 `/daily-plan` 中以显式操作生成、查看、编辑并采用一项每日计划建议。
- 采用编辑后的建议只创建 `CONFIRMED` 软 Event；源 Task 保持 `OPEN` 且完整资源不变。
- 刷新后从 Core 重新读取 `APPLIED` 状态和已保存时间块。
- 日程版本改变后的真实决策请求返回 `DAILY_PLAN_BASE_VERSION_STALE`，且没有额外 Event。
- 未配置 Provider 的真实接口保持诚实的 409；自动化没有保存、读取或发送真实 DeepSeek 凭据。

## 可复现操作与 API 错误检查

1. 由 `scripts/run-e2e.mjs` 启动隔离 Core/Web 端口与临时 `EV_DATA_DIR`；建立唯一 Owner。
2. 对每个浏览器上下文创建确定性 `OPEN` Task 和对应日期的 TimeRequest。
3. 打开 `http://127.0.0.1:3217/daily-plan`，选择测试日期，点击“生成每日计划”，编辑起止时间，点击“采用安排”。
4. 确认真实 `POST /api/core/daily-plans/proposals/:id/decisions` 为 200；刷新并重新选择日期，确认 `已采用`；读取 `/api/core/today?date=...` 确认 `13:00–14:00` 的软 Event；读取 Task 确认仍为初始 `OPEN` 实体。
5. 不提供任何 Provider credential 时，真实 `POST /api/core/daily-plans/generate` 返回 `409 DAILY_PLAN_PROVIDER_NOT_CONFIGURED`。
6. 为 stale 草案插入日程变化后，以原草案版本提交真实 decision API；确认 `409 DAILY_PLAN_BASE_VERSION_STALE`，刷新 UI 后为 `STALE`，当天 Event 集合中没有草案请求标题。
7. 两个页面自创建起持续收集 `console` warning/error、`pageerror` 与页面 401 响应；最终附件均为空。没有降级或忽略 console/error 门禁。
