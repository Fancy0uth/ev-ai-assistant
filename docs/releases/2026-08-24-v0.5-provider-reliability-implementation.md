## 1. 本版交付

v0.5 把 Daily Plan 的 Provider 调用从“可调用”收紧为可恢复、可审计、默认失败关闭的本地链路。

```text
Owner action
  -> Web semantic correlation + Idempotency-Key
  -> BFF request/response header allowlist
  -> Owner-scoped idempotency record and lease claim (SQLite short transaction)
  -> provider call outside SQLite transaction
  -> frozen model/response policy + quota/timeout checks
  -> matching lease token finalizes redacted metadata and response snapshot
  -> replay returns the original safe response; mismatch fails with 409
```

已实现的边界：

- SQLite v18 仅加法：`idempotency_records`、`provider_call_logs` 和 Daily Plan Run 的 lease/attempt/deadline/terminal metadata；迁移测试覆盖既有业务数据与 credential metadata 保留。
- `POST /v1/daily-plans/generate`、`POST /v1/daily-plans/proposals/:proposalId/decisions`、`POST /v1/proposals/:id/decision` 都强制 Owner-scoped `Idempotency-Key`。
- 同一语义请求 replay 首次安全响应；同 Key 不同 operation/resource/body hash 返回 `409 IDEMPOTENCY_CONFLICT`；有效执行中的同 Key 返回 in-progress 语义；decision 的 claim/业务状态/响应快照在单一 SQLite transaction 中处理。
- DeepSeek adapter 只接受冻结的 endpoint、`deepseek-v4-flash`/`deepseek-v4-pro`、非流式结构化响应和 allowlisted `finish_reason`/usage；未知、截断、工具调用、超时、配额或不完整响应均失败关闭。
- Provider 调用不在 SQLite transaction 内；lease token 阻止晚到响应，至多恢复一次，第二次失效收敛到稳定终态。持久日志只保存 policy 允许的计数、状态、模型、日期、耗时和本地错误码，不存 Key、Authorization、prompt、completion 正文、原始 request/response。
- Web 对 prepare/approve/generate 建立 id/run/localDate/version/payload/action 关联。schema 合法但语义不一致时停止，不继续生成或写入。
- 版本、health、package、run 和 Provider log 的应用版本统一为 `0.5.0`。

## 3. 浏览器证据与测试 fixture 边界

每日计划浏览器 E2E 使用 runner 自己创建和清理的 `EV_DATA_DIR`、端口 4327/3217、唯一测试数据及测试依赖注入的 Fake Provider。实际覆盖：

1. Owner 从 Setup/Login 页面进入；
2. Daily Plan 走“准备外发内容 -> 批准外发内容 -> 调用 Provider 生成草案”；
3. 同一浏览器请求的同一幂等键 replay 返回 `Idempotency-Replayed: true`；相同键配不同语义请求返回 `409 IDEMPOTENCY_CONFLICT`；
4. 未配置 Provider 返回安全失败；草案部分采用、刷新及日程版本过期路径仍可用；
5. iPhone touch 视口检查触摸目标、无横向溢出与浏览器 console/page error；
6. Provider 设置页在桌面、390x844、320x800 下保持未配置状态，Key 输入为 password 类型，且不会自动触发连接测试。

`apps/core/e2e/daily-plan-test-bootstrap.ts` 会在上述隔离测试期间直接写入一个非真实 credential marker，以使 Fake Provider 可被确定性调用。它是 **out-of-band 测试基础设施**：不证明 Owner UI -> Core -> DPAPI 的生产凭据路径，也不证明真实 DeepSeek 请求。DPAPI port、credential service 和响应脱敏由单元/集成测试覆盖；真实 Key 和真实网络调用没有发生。
