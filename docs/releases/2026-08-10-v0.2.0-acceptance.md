## Sentrux 与已知限制

Sentrux 主会话 20260810-045745 在未更新 baseline 的前提下记录 quality signal 9756 到 9671（-85）；cycles=0、god_files=0。此结果不被标为通过，已作为 P2-05 记录在改进规格中。主要可维护性风险是 AgentWorkspace 圈复杂度 35 超过工具默认 25，以及工具把新增测试源和单作者历史纳入总信号。下一版应拆分该组件、补齐 .sentrux/rules.toml，并在重新建立有意基线前复核该信号。

其他已接受限制：

- P2-01：Tasks 加载动画尚未遵循 reduced-motion。
- P2-02：Task 竞态组合测试矩阵尚不完整。
- P2-03：Code Intel/Sentrux 对测试源码和部分非原生解析面的结构精度有限。
- P2-04：Agent 跨会话草稿/错误是短暂共享状态，尚未拆为每会话状态。
- P3-01：部分目标日期视觉标签重复；真实 Provider、长期记忆、生活/外部集成均属于后续路线。

1. 使用新的空 EV_DATA_DIR 启动 Core 与 Web；不要复用含现有 Owner 的目录。
2. 打开 http://127.0.0.1:3000/setup，自行创建唯一测试账号。
3. 在 /today、/tasks、/agent 间切换并刷新/前进/后退。
4. 在 /tasks 创建、编辑、完成、延期、取消任务；保留一个浏览器窗口制造 version conflict，确认页面显示服务端最新值而不静默覆盖。
5. 打开 /agent；未配置 Provider 时输入应禁用，直接调用消息资源应得到 503 且刷新后没有新消息。
6. 登出后访问 /api/core/tasks，确认得到 401；浏览器控制台不应出现 warning/error/pageerror。
