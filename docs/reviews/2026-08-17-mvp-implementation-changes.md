# 2026-08-17 本地 MVP 实现变更说明

## 变更目的

把旧版“任务 + 普通 Agent 面板”原型转换为可验证的本地日常控制台基础：日程为骨架，每个专业模块拥有不同的数据与页面，AI 保持为可安全接入的框架而非假聊天。

## 核心变更

| 领域 | 变更 | 用户可见结果 |
| --- | --- | --- |
| Today | 聚合日程、任务、Proposal 和恢复 Signal；新增模块快捷入口与按领域跳转 | 首页打开即能看到今天的安排和去处理的入口 |
| 日程/课程 | Term、Course Import Run、Proposal、日计划 Job、课程资料引用 | 可以先固定学期和课程资料；截图识别在未接 Provider 时诚实阻断 |
| 健身 | 本地 check-in 与确定性恢复评估 | 可记录当天身体状态，Today 能读取其恢复信号 |
| 饮食 | 已确认餐食记录和营养合计 | 不需要伪造 AI，就能先保存明确摄入数据 |
| 记忆 | SQLite revision、事务内 Markdown 投影、查看/编辑/历史/恢复/永久删除 API 和工作区 | 形成可检查、可回退且不会半写入的本地 Hermes 风格记忆基础 |
| 项目 | 显式 scope、真实路径校验、敏感文件排除、allowlist 快照 | 可让未来项目 Agent 了解规划资料，同时没有写项目能力 |
| Web | 新增六个真实工作区路由，桌面/移动保持可读；BFF 支持 PUT；课程链接限 HTTP(S) | 不是点按无反应的单页假导航，也不会渲染危险链接 |
| 测试 | 加入模块组件测试、Core 记忆/项目测试、四个浏览器 E2E spec、Windows 受管 runner | 测试数据不碰用户数据库；若测试端口被占用会拒绝运行而非借用用户服务；成功后还原 Next 类型引用并清理测试缓存 |

## 数据迁移

新增迁移是加法迁移：记忆 revisions、已确认餐食、课程资料、只读项目 scope 等均不重写已有 Owner、Task 或 Agent 会话。迁移测试覆盖从旧 schema 升级后保留既有数据的场景。

## 对现有使用方式的影响

- 首次预览依然没有默认账号，必须在 `/setup` 建立唯一 Owner。
- 现有 Task 仍可使用，Today 会按领域链接到项目/学习/饮食等模块。
- 未配置 Provider 的状态是产品行为，不是报错兜底：系统不会制造聊天回复、课表识别或健康建议。
- 数据仍完全本地；本轮没有新增云端账号、遥测或外部 API 上传。
