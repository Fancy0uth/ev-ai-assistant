## Blocking finding

### P1-ARTIFACT-001 — WebP frame headers are mistaken for actual VP8/VP8L image content

**State:** **OPEN — the previous VP8X-only repair is incomplete.**

Evidence:

- `apps/core/src/modules/calendar/image-metadata.ts:91-106` treats a 10-byte VP8 frame header or 5-byte VP8L header as sufficient to set `imageKind` and dimensions. It validates the signature fields but does not establish that compressed frame data exists or can be decoded.
- `apps/core/src/modules/calendar/image-metadata.ts:124-135` returns those dimensions once container/feature consistency checks pass.
- `apps/core/src/modules/calendar/import-service.ts:72-87` invokes this parser before storage, but because the parser accepts these objects, `store.write()` and the artifact-row insert are reachable rather than returning 422.
- `apps/core/tests/course-import.test.ts:129-195` now correctly rejects VP8X-only and inconsistent RIFF/chunk declarations, but has no valid-size, header-only VP8/VP8L case. Its malformed VP8/VP8L samples declare a one-byte chunk, so they do not exercise this boundary.
- A fresh offline parser probe constructed exact-size RIFF objects containing only a VP8 10-byte frame header and only a VP8L 5-byte header. `readImageMetadata()` accepted both as 1x1 WebP (`30` and `26` bytes respectively).
- A fresh local Chromium probe passed the same byte arrays to `createImageBitmap()`. Both failed with `InvalidStateError: The source image could not be decoded.` No network or external provider was involved.

Impact: an undecodable object crosses the private artifact trust boundary, is persisted as verified `image/webp`, and can later reach an approved image-parsing/Vision call. This violates the explicit requirement that WebP uploads contain actual VP8/VP8L image content and that extension/header-only files receive 422 before persistence and image parsing calls.

Smallest required repair contract: make WebP acceptance depend on a real decodable VP8/VP8L payload (or a local decoder that fails closed), while retaining RIFF/chunk/feature validation and byte/pixel limits. Add upload-level regression cases for exact-size header-only VP8 and VP8L objects and assert 422, zero artifact rows/files, and zero Vision calls. Keep a known-good, independently decodable VP8 and VP8L fixture so the check does not become extension/header matching under another name.
