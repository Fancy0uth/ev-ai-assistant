## 1. 执行摘要

v0.4 已把 v0.3 的关键断链补成一条可运行、可审计、默认 fail-closed 的本地产品闭环：

```text
Owner UI 创建带排程 Task
  → 同一 SQLite Unit of Work 写 Task + ACTIVE TimeRequest
  → prepare 只生成本地 preflight
  → Owner review/edit/exclude
  → approve
  → explicit generate（Provider 在 SQLite transaction 外）
  → Pending Daily Plan Proposal
  → Owner decision transaction
  → Event + Proposal terminal state + audit
  → Today 与真实 Task/Event/Project 详情 URL
```

迁移、生命周期、Owner 隔离、授权前置、排除项授权、事务边界、确认写入和 Web 竞态均有实现与聚焦测试相互印证。本次规定的最小验证全部 exit 0，共运行 103 个测试；聚焦 Playwright 用例从 UI 创建真实业务输入，并完成 preflight、测试 Fake、确认、Today 和三个可刷新详情 URL。

### P2 — EVIDENCE-001：E2E bootstrap 仍直接写测试凭据，证据不是“任意 SQLite mutation 为零”

`apps/core/e2e/daily-plan-test-bootstrap.ts` 会在 generate request 前后，直接向 `provider_credentials` 插入/删除一个 marker。它不注入 Owner、Task、TimeRequest、preflight、Proposal 或 Event，且仅存在于三重闸门保护的测试 bootstrap；所以它没有伪造本次要证明的 UI-origin 业务链，也不构成 production Fake 入口。

但从字面上说，整套 E2E 进程并非“任何 SQLite mutation 都为零”。当前证据应精确表述为：**业务输入与确认写入无 direct API/SQLite setup，唯一 out-of-band SQLite 写是测试凭据夹具**。这不阻断 v0.4 foundation；v0.5 的真实 DPAPI/Owner Key 人工验收必须取代它来证明真实 Provider 配置链。

### P2 — WEB-BOUNDARY-001：preflight Web 响应只做状态校验，缺少完整 action semantic correlation

`use-daily-plan-preflight.ts` 对 prepare response 只要求 `AWAITING_APPROVAL`，对 approve response 只要求 `APPROVED`；没有同时核对 returned preflight 的 `id/runId/localDate` 与发起动作一致、version 单调增加。generate response 也没有把 Proposal `runId/localDate` 与已批准 preflight 关联。当前 Core route 在正常执行中返回正确对象，epoch/abort guard 又消除了真实 stale response 竞态，因此本次没有可由现有产品链直接复现的越权或误生成，级别不升为 P1。

这是与 Manual Event 已采用的 endpoint/action correlation 不一致的防御纵深缺口。v0.5 应增加 action-specific predicates 和 wrong-id/wrong-date/wrong-run/non-incrementing-version 回归测试，确保 schema-valid 但语义不一致的 BFF/Core response 也 fail closed。

### P3 — UI-ACCESSIBILITY-001：两个已接受的可访问性细节仍未收口

Detail error retry button 尚未纳入统一 44px/移动全宽 selector；approve 在 `approving` 时 disabled，但没有 `aria-busy=true`，busy cursor/辅助技术语义不完整。不会绕过确认或阻断主链。

### P3 — MAINTAINABILITY-001：响应式 CSS 仍有重复规则

`dashboard.css` 的 42rem 附近响应式规则存在重复，集中式文件继续增长。现有 focused source/CSS tests 能确认关键 stack/focus selector，但不是 CSS 去重或视觉回归系统。
