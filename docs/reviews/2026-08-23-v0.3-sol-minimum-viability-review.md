## 1. 执行摘要

当前版本已经不是静态 Demo：单 Owner、本地 SQLite、真实路由、Provider 密钥入口、DPAPI 适配、每日计划 Proposal、版本冲突保护、07:00 定时器和响应式页面均有实际实现与自动化测试。

但是，最核心的产品闭环仍在一个关键位置断开：**用户通过页面创建的 Task 不会成为 Daily Plan 读取的 `TimeRequest`**。生产代码中不存在创建 `TimeRequest` 的调用；E2E 则直接向 SQLite 注入 `TimeRequest`，再用 Fake Provider 验证审核页面。因此，测试证明了“已有人工测试夹具时，计划可以被审核和应用”，没有证明“真实用户输入任务后，AI 能安排这些任务”。

此外，Web 明确只监听 `127.0.0.1`，真实 iPhone 无法从另一台设备访问；现有 iPhone 证据是同机 Chromium 触摸/视口模拟，不是物理 iPhone Safari、私网 HTTPS 或远程网络验收。

因此应区分两个结论：

- **工程质量门：PASS。** 当前已实现代码稳定、类型正确、构建成功，未发现 P0 数据损坏或明文密钥问题。
- **产品最小可行性：FAIL。** “真实行动输入 → AI 排程 → 人工确认 → 回到 Today”尚未贯通，远程 iPhone 入口也不可用。

当前版本适合作为**技术预览和后续开发基线**，不适合标记为“已完成 MVP”或交付为日常稳定版。

## 2. 本次最小可行性判定标准

本次没有用完整产品蓝图要求当前版本一次实现所有 Agent，而是检查以下最小链路：

1. 新数据目录可创建唯一 Owner，并能正确登录、退出和保护资源；
2. Today 首屏真实显示当天 Event、具体 Action/Task、Signal 和 Proposal；
3. 用户可在页面创建一件真实行动或日程，并让它成为 Daily Plan 的输入；
4. 用户可配置 DeepSeek，系统只发送受约束上下文，不伪造模型结果；
5. AI 计划必须可解释、可编辑，只有确认后才写入日程；
6. 07:00 或首访补偿不会重复写入，也不会绕过确认；
7. 桌面和用户要求的远程 iPhone 浏览器都能到达并完成核心流程；
8. 常开 Windows 主机至少具备可恢复、可诊断的日常运行边界。

## 5. 已确认发现

### P1 — MVP-001：Task/Action 到 Daily Plan 的生产链路断开

**证据：**

- `apps/core/src/modules/tasks/service.ts:42-56` 只写入 `tasks`；
- `apps/core/src/modules/calendar/repository.ts:313-340` 定义 `createTimeRequest()`，但生产代码没有调用它；
- `apps/core/src/modules/daily-planning/context-service.ts:117-126` 只从 `context.timeRequests` 构造模型输入；
- `apps/web/e2e/daily-plan-review.spec.ts:88-127` 绕过 UI，直接向 SQLite 创建 `TimeRequest`。

**影响：** 用户在 Today/Tasks 创建的工作、学习或生活任务不会进入 AI 排程。真实新数据库只能得到空计划，或依赖不存在的上游领域 Agent 先创建 TimeRequest。

**决定：** 有效且必须修复。它是当前最小闭环的第一阻断项。

### P1 — MVP-002：模型输入缺少任务语义

**证据：** `apps/core/src/modules/daily-planning/provider.ts:13-21` 只包含 `contextRef`、时长、优先级和可用时间；没有安全化后的标题、领域、截止日期或处理目标。

**影响：** 即使补上 Task → TimeRequest，模型仍只能做匿名装箱排程，不能理解“写作业”和“修复项目 Bug”的差异，也不能给出用户要求的任务分析。

**决定：** 有效且必须与 MVP-001 一起修复。新增语义字段前，必须先提供调用前可见、可编辑的最小 context packet，不能直接发送完整任务或健康原文。

### P1 — MVP-003：Today 没有事项级处理路径，日程输入也不可独立完成

**证据：**

- `apps/web/src/components/today/day-console.tsx:53-64` 的 Event 是纯文本；
- `apps/web/src/components/today/day-console.tsx:75-83` 和 `task-list.tsx:76-82` 只按领域跳到模块根路由，不携带事项 ID；
- `apps/web/src/components/schedule/schedule-workspace.tsx:100-130` 只有建立学期和课表截图入口，没有手工 Event/会议创建入口；
- 生产环境没有 `CourseScheduleVisionProvider` adapter，因此截图流程当前不能形成真实课程 Proposal。

**影响：** “点击今天的一件事进入对应处理页”和“先建立一个可供计划使用的真实日程”都不能稳定完成。

**决定：** 有效且必须修复，但只需实现一个事项详情和一个手工日程垂直链，不应扩张为完整日历产品。

### P1 — MVP-004：真实 iPhone 远程入口不存在

**证据：**

- `apps/web/package.json:7,9` 的 dev/start 均使用 `--hostname 127.0.0.1`；
- `README.md:54-61` 明确说明当前技术预览不支持局域网或公网访问；
- 自动化使用 Playwright Chromium 的 iPhone/touch context，不是 Safari 或另一台设备。

**影响：** 页面可以响应式缩小，但用户的 iPhone 无法连接这台常开电脑。

**决定：** 对“本机技术预览”不是阻断；对用户已经确认的远程 iPhone 使用场景是 P1。必须在宣称个人稳定版前交付私网 HTTPS，只暴露 Web，继续保持 Core/SQLite loopback。

### P1 — SCOPE-001：已批准 MVP 与 v0.3 延期清单冲突

`docs/product/MVP-SCOPE.md:13-17,56-103` 把课表识别、公开课程检索、训练 Proposal、自然语言营养、分域记忆等定义为 MVP 垂直链；`docs/technical/IMPLEMENTED-MVP-DESIGN.md:47-55` 和 v0.3 规格又将其中多项明确延后。

**影响：** 同一版本既被称为 “MVP”，又只完成 Daily AI Control Loop 切片，验收人员无法判断完成标准。

**决定：** Sol 将这些全部当作 P3 是一次**契约误读**。相对于 v0.3 单切片它们是延期项；相对于已批准的完整 MVP，它们仍未完成。下一轮必须先冻结版本命名和验收边界，不能用改文档掩盖缺失能力。

## 6. 非阻断但应紧接处理的问题

### P2 — RELIABILITY-001：崩溃遗留 Run 会长期显示生成中

`automation-service.ts:115-117` 看到任意既有 Run 就跳过；`today/routes.ts:49-54` 把 `CREATED/CONTEXT_READY/GENERATING` 显示为 `GENERATING`。进程若在调用期间退出，启动时没有把超时 Run 标记失败或恢复，首访补偿也会被既有 Run 阻断。

### P2 — RELIABILITY-002：缺少可重放的 Idempotency-Key

ADR-009 要求 `expectedVersion + Idempotency-Key`，当前审核请求只有 `expectedProposalVersion`。事务、版本和唯一决策约束能防止多数重复写，但网络丢响应或双标签页只能得到冲突，不能安全返回第一次结果；生成请求也没有请求级防重复收费。

### P2 — PRIVACY-001：Context 只能事后查看

`daily-plan-workspace.tsx:133-145` 点击生成后立即调用 Provider；`371-408` 只有草案生成后才能展开 Context Manifest。已批准规格要求调用前可见并确认外发摘要。当前只发送匿名排程字段和恢复枚举，实际风险受限；在加入任务语义或健康文本前必须补齐 preflight。

### P2 — OPS-001：常开电脑缺少恢复与可观测性闭环

当前 README 仍要求两个开发终端启动；没有 Windows 常驻服务、SQLite 一致性备份/恢复命令、保留策略和持久化脱敏日志。WAL 模式下只复制 `app.sqlite` 也不足以证明可恢复。

### P2 — RELEASE-001：运行版本仍报告 0.2.0

根包、Web、Core、Contracts、Domain、`CHANGELOG.md` 和 `/v1/health/live` 都仍为 `0.2.0`，而文档称当前为 `0.3.0` 候选。该问题不破坏功能，但会使日志、验收、回滚和用户报告无法准确对应代码。

### P2 — MAINTAINABILITY-001：Code Intel 只提供启发式结构证据

本次扫描是 `native-minimal`，call graph 未知，Markdown/CSS 不参与语义分析。`dashboard.css` 仍是集中大文件。它不阻断 MVP，但不能把 Code Intel `pass` 解释为架构无债务。

## 8. 最小修复顺序与边界

1. **冻结版本事实。** 明确当前版本是“v0.3 Daily Control Loop 技术预览”还是完整 MVP；同步 package、health、CHANGELOG 和验收名称，不删除批准 MVP 中未完成的需求。
2. **贯通一条真实行动链。** Task/Action 创建或明确“加入今日计划”时生成 versioned `TimeRequest`；Provider 获得用户允许的最小语义（安全化标题/领域/截止时间/时长/优先级）；E2E 必须从 UI 创建，不再直接插库。
3. **补一个真实日程和事项详情链。** 浏览器内手工创建 Event/会议，Today 链接到带 ID 的任务/Event/课程/项目详情；暂不实现完整课表 OCR、日历同步或多模块 Agent。
4. **完成真实 AI 运行验收。** 用独立数据目录和 Owner 自备 Key 验证 DPAPI 保存、连接、真实生成、失败脱敏、Context preflight、重启遗留 Run 恢复和请求幂等；测试日志不得包含 Key 或正文。
5. **完成个人稳定版入口和运维。** 私网 HTTPS 只暴露 Web，以物理 iPhone Safari 验收；增加 Windows 常驻启动、SQLite 一致性备份/恢复和最小脱敏日志/健康状态。

在第 2 步通过之前，不建议并行扩张 OCR、动作 RAG、营养数据源或多 Agent 协商。先让一个真实任务能被 AI 看见、解释、安排并经用户确认回到 Today，才构成最小可行产品。

## 9. 最终结论

**结论：FAIL。**

失败的是产品最小闭环，不是工程基础。当前提交已经具备可靠的本地模块化骨架、安全的 Proposal-only 方向和较完整的自动化保护；但核心真实输入链、事项级处理入口和远程 iPhone 入口仍缺失。完成第 8 节前五项后，应使用同一标准重新进行 Sol 独立审查和 Owner 真实验收。
