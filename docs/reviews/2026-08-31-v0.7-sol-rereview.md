## Blocking findings

### V07-MIG-006 — P1 — v21 certifies an already-invalid v20 database

- **Path + line:** `apps/core/src/storage/migrations.ts:1511-1754`
- **Reproduction:** Create an in-memory database through v20, use the repository's established two-Owner test technique, insert an Owner-A `fitness_check_ins_v2` row whose `signal_id` belongs to Owner B, then call `runMigrations(db)`. The isolated probe exited 0 and printed:

  ```json
  {"migrationSucceeded":true,"version":{"version":21},"row":{"child_owner":"owner-a","parent_owner":"owner-b"}}
  ```

- **Expected:** The corrective migration must not record v21 while any v0.7 lineage edge violates the Owner-correlated invariant. It must either fail closed with the invalid edge identified or produce a database in which the invariant holds.
- **Actual:** v21 creates indexes and insert/update triggers and records itself successfully while preserving the invalid row. SQLite triggers are not retroactive.
- **Root cause:** The remediation tests only valid v20 preservation and post-v21 negative writes. The migration has no preflight query, rebuild, quarantine, or abort for pre-existing violations.
- **Required action:** Before recording v21, audit every corrected v0.7 edge inside the migration transaction and abort on any mismatch. Add corrupt-v20 upgrade cases for every edge and assert that v21 is not recorded and no invalid row is silently certified.

### V07-FIXTURE-008 — P1 — fixture gates trust one self-declared enum

- **Path + line:** `apps/core/src/app.ts:112-124`; `packages/contracts/src/health-capabilities.ts:13-34,90-96`; `apps/core/src/modules/nutrition/provider.ts:32-39`
- **Reproduction:** Start `buildApp()` with `NODE_ENV=production` and a local provider descriptor `{providerId:'v07-test-fixture', adapterKind:'PRODUCTION_ADAPTER', evidenceKind:'AUTOMATED_TEST_FIXTURE'}` without `v07TestAdapterGate`. The isolated command exited 0 and printed:

  ```json
  {"started":true,"nodeEnv":"production","descriptor":{"providerId":"v07-test-fixture","providerLabel":"synthetic fixture","adapterKind":"PRODUCTION_ADAPTER","evidenceKind":"AUTOMATED_TEST_FIXTURE"}}
  ```

- **Expected:** Any fixture identity or fixture evidence marker requires `NODE_ENV=test`, the explicit runner gate, and contained DB/data/artifact paths; inconsistent descriptor combinations must be rejected before listening. The frozen plan makes a fixture outside its gates an automatic FAIL.
- **Actual:** `fixtureRequested` checks only `descriptor.adapterKind === 'TEST_FIXTURE'`. The provider interfaces and response schema permit contradictory provider/evidence/adapter combinations, so fixture identity/evidence can be mislabeled as a production adapter and bypass every gate.
- **Root cause:** Descriptor fields are independent enums rather than a discriminated invariant, and startup derives security policy from only one field.
- **Required action:** Define strict discriminated provider descriptors and validate injected ports at composition. Treat any fixture provider ID, fixture source, `AUTOMATED_TEST_FIXTURE` evidence, or `TEST_FIXTURE` adapter marker as fixture composition and require all gates. Add contradictory-descriptor negative tests for both provider ports.

### V07-REPLAY-013 — P1 — terminal 429 replay violates the frozen header contract

- **Path + line:** `apps/core/src/modules/fitness/service.ts:262-265`; `apps/core/src/modules/nutrition/service.ts:174-177,271-274`; `apps/core/src/modules/health-loop/idempotency-service.ts:49-59,153-163,204-206`; `apps/core/src/http/api-error.ts:42-47`
- **Reproduction:** In an isolated temporary database, create an Owner/check-in, seed five consumed `WORKOUT_TEXT_SELECTION` calls for the same local date, then submit the same assisted command twice with one idempotency key. The authenticated probe exited 0 and returned:

  ```json
  {"first":{"status":429,"retryAfter":null,"replayed":null,"body":{"error":{"code":"RATE_LIMITED","message":"今日训练文本能力调用次数已达上限"}}},"replay":{"status":429,"retryAfter":null,"replayed":"true","body":{"error":{"code":"RATE_LIMITED","message":"今日训练文本能力调用次数已达上限"}}},"bodiesEqual":true}
  ```

- **Expected:** The frozen 429 response includes `Retry-After`; a terminal replay preserves status/body, emits `Idempotency-Replayed: true`, and retains the required retry metadata.
- **Actual:** Status and body replay exactly and the replay marker is present, but `Retry-After` is absent from both the first response and replay.
- **Root cause:** Capability quota failures construct a plain `ApiError` without retry metadata. Idempotency persistence stores only status/body, and `V07IdempotencyReplayError` cannot reconstruct terminal response headers.
- **Required action:** Give all capability-quota errors a frozen retry value and persist or deterministically reconstruct replay-relevant response metadata. Add first-response and replay assertions for all three capabilities.
