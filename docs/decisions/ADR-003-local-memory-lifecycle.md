# ADR-003: 采用分层、可追溯且有容量上限的本地记忆

## Status

Accepted

## Date

2026-08-04

## Context

用户需要类似 Hermes 的长期累积记忆，但不希望完整聊天记录不断增长或占用大量本地空间。记忆还必须可检查、可编辑、可删除和可导入导出。

## Decision

Bridge 按“事件缓冲 → 周度/项目摘要 → 长期卡片 → 固定卡片”保存记忆。默认不保留完整对话。所有摘要和卡片记录来源、修订和派生关系；重复合并、过期、导入和删除为原子操作。源数据删除时，系统级联删除或重新生成派生内容。

使用 20 MB 软上限和 50 MB 硬上限，以序列化 UTF-8 正文及索引的实际字节数计量。固定卡片不自动删除；达到硬上限时拒绝新增/导入并引导用户处理。

## Alternatives Considered

### 永久保留全部对话

实现直观，但成本和隐私风险持续增长，检索噪声也会累积。

### 只保存当天摘要

很轻量，但无法形成稳定偏好、项目背景和长期协作记忆。

## Consequences

- 需要为来源追踪、级联删除、容量预检和导入回滚提供测试。
- 初版优先采用标签与全文检索，不以高成本向量数据库作为前置条件。
