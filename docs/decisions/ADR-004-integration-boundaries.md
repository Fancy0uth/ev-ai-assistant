# ADR-004: 日历快照导入与 GitHub 手动只读刷新

## Status

Superseded by ADR-007.

## Date

2026-08-04

## Context

用户希望在任务和日程中看到 Apple 日历、GitHub 工作项，但 v1 的首要目标是可靠的 Web 产品，而不是复杂的外部自动化。

## Decision

日历仅支持用户本地选择 `.ics` 文件的快照导入，不提供持续 Apple 同步或任何写回。GitHub 仅在用户触发时刷新只读数据；转换为任务需用户显式操作，并以不可变外部标识保证来源与幂等性。

导入和刷新必须展示成功、部分成功、失败和数据陈旧状态。任何第三方内容都按不可信输入验证、清理并显示。

## Alternatives Considered

### 自动双向日历同步

体验更顺畅，但 Web 环境下 Apple 连续同步和冲突处理明显扩大范围，也引入外部写入风险。

### GitHub 双向写入

自动化更强，但不符合 v1 的用户控制原则，错误后果更高。

## Consequences

- 需实现 iCalendar 时区、重复、取消和重导入的确定性规则。
- GitHub 同步需处理分页、限流、删除和部分失败，而不以“刷新成功”掩盖不完整数据。
