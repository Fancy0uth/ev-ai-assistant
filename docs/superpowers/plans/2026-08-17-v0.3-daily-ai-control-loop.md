# v0.3 Daily AI Control Loop 实施计划

## 实施目标

交付一条真实的 DeepSeek 每日排程链路：安全配置 → 最小上下文 → 结构化草案 → 用户确认 → Today 更新时间轴。详细产品和技术契约见[规格](../specs/2026-08-17-v0.3-daily-ai-control-loop.md)与 [ADR-012](../../decisions/ADR-012-dpapi-secrets-and-proposal-only-daily-ai.md)。

## 依赖图

```text
SecretStore/Provider profile
  └─ DeepSeek adapter + connection test
       └─ Daily plan contracts + additive migration
            └─ context builder + deterministic validator
                 └─ proposal review/apply API
                      └─ Today console redesign + responsive E2E
```

## Phase 1: 安全的真实 Provider

### Task 1 — V3-01: 冻结密钥、Provider 状态与错误契约

**验收：** Key 写入请求从不返回；状态仅含非敏感字段；未认证拒绝；契约测试涵盖失败分类。

**验证：** Contracts focused tests、`npm run typecheck`。

**依赖：** 无。**预计文件：** Contracts schema/test、Provider types（3–4）。

**本任务的边界澄清：** 本任务只冻结跨层契约，不注册凭据 HTTP 路由、不保存密钥；路由的 Owner 鉴权拒绝在 Task 3 与真实服务一起验证，避免在没有安全存储时留下可调用的写入端点。

**契约决议（必须原样遵守）：** 新增 `DeepSeekCredentialMetadata`（`providerKey: 'DEEPSEEK'`、`state: 'NOT_CONFIGURED' | 'CONFIGURED'`、`updatedAt: ISO 时间或 null`、`lastConnectionTest`）；连接测试结果为 `SUCCEEDED` 或 `FAILED`，只有 `FAILED` 可携带 `AUTHENTICATION_FAILED | RATE_LIMITED | NETWORK_ERROR | INVALID_RESPONSE | PROVIDER_UNAVAILABLE` 之一。写入输入仅为严格对象 `{ apiKey }`（trim 后 1–512 字符）；删除输入仅为严格对象 `{ confirmation: 'DELETE' }`。所有公开状态响应均为严格对象，且不得包含 `apiKey`、密文、尾号或任意密钥派生值。保留 v0.2 的 `ProviderProfile` 与 `/v1/providers` 契约不变。

### Task 2 — V3-02: 实现 SecretStore Port 与 Windows DPAPI adapter

**验收：** 保存/读取/替换/删除均经 Port；Fake 能完整测试；没有明文 SQLite 或日志；非 Windows 明确不可用。

**验证：** Core unit tests、敏感字符串扫描、`npm test`。

**依赖：** V3-01。**预计文件：** secret port、Windows adapter、service、test（4–5）。

### Task 3 — V3-03: 实现 DeepSeek adapter、Provider 设置与连接测试

**验收：** 真实 Key 可在 Owner 设置页配置并测试；超时/401/429/无效响应有准确状态；自动化注入 Fake Provider。

**验证：** Core route/service tests、Web component test、人工一次连接测试。

**依赖：** V3-02。**预计文件：** adapter/service/routes、settings component/test（最多 5）。

### Checkpoint A

- [ ] 未配置、保存、替换、连接失败与成功状态完整可见。
- [ ] `npm test`、typecheck、lint、diff check 通过。
- [ ] 评审 Key 不会出现在 API、SQLite、日志和 Memory。

## Phase 2: 可确认的每日计划

### Task 4 — V3-04: 定义 Daily Plan Run、Proposal Item 与 Context Manifest 契约

**验收：** 输入/输出 JSON 结构、版本号、决策状态与错误码固定；模型输出不能包含未声明写操作。

**验证：** Contracts/Domain RED→GREEN tests。

**依赖：** V3-01。**预计文件：** contracts、domain rule、tests（3–4）。

### Task 5 — V3-05: 加法迁移与 Daily Planning Context Builder

**验收：** 迁移保留现有数据；仅汇总今日 Event/Action/恢复枚举和偏好；Manifest 可读且不含 Key/健康原文。

**验证：** 001→新版本迁移测试、context redaction test。

**依赖：** V3-04。**预计文件：** migration、repository/service、tests（4–5）。

### Task 6 — V3-06: 生成、校验和保存 Daily Plan Proposal

**验收：** Fake DeepSeek 返回合法 JSON 能产生草案；硬 Event 冲突、越界时间和基础版本冲突被拒绝；失败 Run 不改变日程。

**验证：** Provider/service integration tests。

**依赖：** V3-03、V3-05。**预计文件：** planning service、validator、routes、tests（4–5）。

### Task 7 — V3-07: 审阅、部分确认和拒绝

**验收：** 用户可编辑/选中草案项；仅已选项目在一次事务中落到时间轴/Action；旧草案不能覆盖新日程。

**验证：** Core integration tests、API version conflict tests。

**依赖：** V3-06。**预计文件：** apply service/routes/repository/tests（4–5）。

### Checkpoint B

- [ ] API 可在不使用前端时完成 generate → inspect → partial apply → Today query。
- [ ] 未配置或模型失败从不写入 Event/Action。
- [ ] 真实 Key 仅做一次人工验收；所有 CI 测试使用 Fake。

## Phase 3: 让首页成为产品

### Task 8 — V3-08: 重构 Today Control Console 信息层级

**验收：** 桌面和 iPhone 首屏同时可见时间轴、具体 Action、恢复摘要和生成计划入口；无数据/未配置有下一步说明。

**验证：** Web component tests、1440×900 和 390×844 screenshot/DOM E2E。

**依赖：** V3-06。**预计文件：** today view、styles、test（3–5）。

### Task 9 — V3-09: 实现 Plan Review UI 与 Context 可见性

**验收：** 用户在界面能看到发送字段类别、草案依据、冲突和每项确认状态；不能在页面读取 Key。

**验证：** Web tests、accessibility focus tests。

**依赖：** V3-07、V3-08。**预计文件：** review component/client/test/style（4–5）。

### Task 10 — V3-10: 07:00 调度、首次访问补偿与端到端验收

**验收：** 同日不会重复生成；错过 07:00 后首访补做；E2E 覆盖真实路径、确认回写、移动布局和零页面错误。

**验证：** Core scheduler tests、独立 `npm run test:e2e`、全仓质量门。

**依赖：** V3-06 至 V3-09。**预计文件：** scheduler/service/test、E2E spec（3–5）。

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| Windows DPAPI 兼容性 | 先完成 V3-02 技术切片；Port + Fake 使其可替换，失败时不进入模型功能。 |
| 模型输出不可靠 | Zod schema、确定性冲突校验、Proposal-only、版本校验。 |
| API Key/健康数据泄露 | 默认最小 context、密文存储、响应/日志 redaction tests。 |
| 首页再次看起来像 To-do | V3-08 以前不做额外模块；验收以首屏时间轴与计划审阅为准。 |
| 07:00 服务重启漏跑 | 以日期幂等键 + 首次访问补偿处理。 |
