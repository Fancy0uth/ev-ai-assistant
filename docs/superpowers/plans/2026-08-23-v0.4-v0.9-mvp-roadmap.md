# v0.4–v0.9 完整 MVP 实施路线

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实施。每个任务都以复选框跟踪，并由独立 reviewer 在进入下一任务前核对规格、diff 与聚焦测试。

**Goal:** 从 `a2a21a8` 的 v0.3 Daily Control Loop 技术预览连续交付到 v0.9 完整本地个人 MVP，同时保持批准的隐私、确认、只读项目和 loopback Core 边界。

**Architecture:** 延续 Next.js Web + same-origin BFF + Fastify loopback Core + SQLite/WAL 模块化单体。各领域先生成版本化 Action/TimeRequest/Proposal，日程协调器产出唯一日程 Proposal；外部 Provider 只通过受限 Port 接收可见、可编辑、最小上下文。

**Tech Stack:** Node 24、TypeScript 6、Next.js 16、React 19、Fastify 5、better-sqlite3 13、Zod 4、Vitest 4、Playwright 1.62、Windows DPAPI。

**Spec:** [`docs/superpowers/specs/2026-08-23-v0.4-v0.9-mvp-design.md`](../specs/2026-08-23-v0.4-v0.9-mvp-design.md)

## Global Constraints

- 基线为 `a2a21a87dcffec14c019f99b3f569998869fc870`；先阅读 v0.3 Sol 审查，不把其 FAIL 改写成 PASS。
- 单 Owner；所有业务、run、记忆、artifact、日志索引和幂等数据都按 `owner_id` 隔离并只存本地。
- Core 始终只绑定 `127.0.0.1`；iPhone 只访问私有、认证、HTTPS 的 Web 边界。
- Provider Key 只经 DPAPI/等价本地机密保护；不进入仓库、SQLite 明文、浏览器、prompt、日志或响应。
- 真实 Provider 未配置或失败时 fail closed；Fake 只允许 `NODE_ENV=test` + 显式 flag + runner-owned 临时目录。
- 高影响写入必须 Proposal + Confirm + version + idempotency + audit；项目集成始终只读，绝不写代码或 Git。
- Prompt、网页、OCR、营养/动作数据、记忆和仓库内容都是不可信数据，不是指令。
- SQLite 迁移只加不删；冻结旧库升级后 Owner、Task、Run、Proposal 和 legacy conversation 不丢失。
- 每个 Terra 任务通常不超过五个产品/测试文件；迁移、文档和生成 lockfile 单列。
- 每项先 RED、再 GREEN、再本任务内重构、聚焦验证和原子 commit。
- v0.5 建立单一版本事实；v0.6–v0.9 每版退出时同步 package、health、run 和 backup manifest 的实现版本，均不称 1.0。
- 安装依赖、真实外部调用、Tailscale/端口/系统服务、真实 restore、push/发布均需执行时主 Agent 单独审批。

## 4. 并行与串行规则

可并行的唯一情况是：上游契约和迁移已合入，两个任务不修改同一文件或同一 SQLite 表族。例如 v0.7 的 exercise catalog importer 与 nutrition provider adapter 可以并行，但它们的 `app.ts` composition、Provider profile contract 和最终 E2E 必须串行收口。

必须串行：

- 每版 Contracts → migration → repository/service → route → Web → E2E；
- 所有修改 `apps/core/src/storage/migrations.ts` 的任务；
- 所有修改 `apps/core/src/app.ts`、BFF、`packages/contracts/src/index.ts`、`apps/web/src/app/dashboard.css` 的任务；
- v0.9 主机配置、物理设备验收和最终完整门禁。

## 5. Terra 执行协议

每次只派发一个任务，输入包含本版计划、绑定设计和依赖 commit。Terra 的允许写入范围就是任务 `Files` 列表；若必须增加产品/测试文件，先停止并由主 Agent 更新计划，不得“顺手”扩范围。

每个任务交付：

```text
RED command + expected failure
GREEN diff
focused test result
affected workspace typecheck
focused eslint
git diff --check
secret-pattern scan
atomic commit SHA
not-touched note
```

Reviewer 按两阶段检查：先检查规格/边界，再检查实现质量。发现与计划不一致时回到同一 Terra 任务修正，不派发新 Agent 猜测修复。

## 6. 版本 Sol 最小冒烟

每版独立计划给出精确命令；共同原则为：

- 只跑该版新增/受影响的 Contracts、Domain、Core、Web tests；
- 只跑受影响 workspace typecheck；
- Web 路由/构建改变时跑一次 `npm run build --workspace @ev/web`；
- Core 启动/迁移/health 改变时跑对应 startup health smoke；
- 只跑一个版本关键 Playwright spec；
- 真实 Provider、物理 iPhone 或主机动作另列审批后的人工证据；
- 不在 v0.4–v0.8 默认跑全仓 E2E。

审查记录路径和必填内容以绑定设计第 9 节为准。审查文件在实际执行时创建；本路线不预建空证据文件。

## 7. v0.9 最终完整门禁

最小冒烟通过后，执行并保留原始摘要：

```powershell
npm test
npm run typecheck
npm run lint
npm run build
npm run test:e2e
npm audit --omit=dev --json
npm test --workspace @ev/core -- tests/database.test.ts tests/migrations.test.ts tests/backup-restore.test.ts
git diff --check
```

随后完成：

1. 冻结 migration v1、v2、v16、v0.8 最新库和 v0.9 backup restore 矩阵；
2. desktop Chromium、mobile WebKit/触摸上下文、物理 iPhone Safari；
3. Windows 重启/登录后自启动、Core/Web health、Provider 未配置 fail-closed；
4. 私有网关 ACL/HTTPS/Web-only exposure，确认 `4311` 从手机、LAN 和公网均不可达；
5. secret scan、日志/备份抽查、Owner/Task/Run/Proposal 计数；
6. 所有 P0/P1 归零后才写 PASS。

`npm audit`、浏览器 runtime 下载、私有网关、Windows 自启动与物理设备操作都需要主 Agent 单独审批。未获批不是成功，也不能由自动化 Fake 替代；review 应记录 `BLOCKED_BY_APPROVAL` 并保持版本未通过。

## 8. 风险与处置

| 风险 | 最早暴露版本 | 处置 |
| --- | --- | --- |
| Task 与 Action 双模型继续漂移 | v0.4 | 用 origin-linked TimeRequest，不删除 legacy Task；详情/API 明确对象来源 |
| 语义上下文扩大隐私外发 | v0.4 | preflight + 字段 policy + editable safe title；无批准不调用 |
| Provider 重复收费/失联 Run | v0.5 | 幂等 request hash、lease/heartbeat、quota、redacted call record |
| OCR/网页提示词注入 | v0.6 | artifact/schema/SSRF/内容上限；数据永远不成为指令 |
| 健身/饮食变成医疗或模型猜数 | v0.7 | deterministic rule、权威 source/version、禁止诊断 schema/copy tests |
| Project Agent 间接写仓库 | v0.8 | local-only authorize、snapshot only、no-optional-locks、前后 hash/Git 证据 |
| 记忆自动压缩抹去事实 | v0.8 | L0 不覆盖、lineage/revision、容量和恢复测试 |
| 远程入口扩大 Core/路径权限 | v0.9 | Web-only private HTTPS、BFF deny local-admin、Core bind invariant、Origin/CSRF |
| WAL 复制得到不可恢复备份 | v0.9 | SQLite backup/checkpoint + manifest + quick_check + restore drill |

## 9. 路线完成定义

路线完成不等于“六份文档已存在”，而是六个版本依次有 PASS 的 Sol smoke review，v0.9 完整集成门禁和物理 iPhone Safari 证据通过，且没有越过审批门。此时可称“v0.9 完整 MVP 实现候选”；是否对外发布、标记 1.0、push 或部署是新的授权和新的发布决策。
