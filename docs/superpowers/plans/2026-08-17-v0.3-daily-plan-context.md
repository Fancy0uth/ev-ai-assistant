# V3-05：Daily Planning Context 与加法迁移

## 目标与边界

本任务建立 AI 每日排程的本地输入边界：用 Owner 与日期读取现有日程数据，构造并持久化一份脱敏 `DailyPlanContextManifest`，同时仅在当前 Core 调用内返回最小 planning packet。它不注册 HTTP 路由、不调用 Provider、不生成 Proposal、不写入 Event/Task/Action/TimeRequest。

已有 `daily_plan_jobs` 与 `proposals` 仍是旧的规则型日程建议流程，保持原样。新增 `daily_plan_runs` 只表示 v0.3 AI 计划的审计生命周期，二者不得互相读写或共享状态。

## Migration 13

仅新增 `daily_plan_runs`：

- `id`、`owner_id`、`contract_version`、`local_date`、`trigger`、`status`；
- `context_manifest_json`（`json_valid`）、`proposal_id`、`failure_code`、`created_at`、`completed_at`；
- SQLite CHECK 复刻 `DailyPlanRun` 的终态约束：`SUCCEEDED` 才可有 `proposal_id`，`FAILED` 必须有失败码，非终态不得有完成时间；
- Owner/date/status 与 owner/created_at 索引；Owner 删除级联；绝不存 API Key、Provider 原文、健康原文、实体标题或 ID 到 Manifest JSON。

`daily_plan_proposals` 与 `proposal_decisions` 在 V3-06/V3-07 各自的持久化切片再加入，避免未使用表及循环外键。本迁移中的 `proposal_id` 是为已冻结的 Run 契约预留的 nullable 引用；V3-05 只创建 `CONTEXT_READY` Run，必为 null。

## Context Builder

`DailyPlanningContextService.prepare(ownerId, { localDate, trigger, now? })`：

1. 读取该 Owner/日期的 `CONFIRMED` Event 与 TimeRequest、`RECOVERY` Signal；不读取 Task 标题、Action、记忆、课程、项目、饮食或其他 Signal 原文。
2. 将 Event 分为硬时间块与确认的软时间块；每个块只保留开始/结束时间和硬性标记。
3. 为按既有 Repository 排序得到的 TimeRequest 分配稳定的当次 `TIME_REQUEST_1…n` 引用；内部 packet 保留对应的本地 `id`、`version`、时长、优先级、可用窗口和固定性。该映射只返回给同一进程的后续 V3-06 服务，不写 SQLite、不进入 Manifest、不发送给浏览器。
4. 只取当天最后一条 `RECOVERY` Signal，并确定性映射为 `READY`（70–100）、`MODERATE`（40–69）或 `LIMITED`（0–39）；没有 Recovery 则为 `NONE`。不保留原始分数、睡眠时长、不适文本或历史。
5. 每次 `prepare` 持久化 `CONTEXT_READY` Run。Manifest 固定列出已评估类别及数量：硬事件、软事件、开放 TimeRequest、Recovery 约束；只含 `DailyPlanContextManifest` 已允许的 field category、日期、创建时间和 `sentAt: null`。

## RED → GREEN 验收

1. 从迁移 12 打开数据库后可看到 migration 13 与 `daily_plan_runs`，且原有 Owner/Task/Provider 行仍存在。
2. SQLite 约束拒绝不一致的 terminal Run、非终态完成时间、无效 JSON 和不属于 Owner 的删除后残留。
3. Context Builder 严格按 Owner/日期读取；排除 `CANCELLED` Event 与非 Recovery Signal。
4. Manifest 能通过 Contracts schema，且序列化文本不出现 Event/TimeRequest UUID、标题、恢复原始数值、`apiKey` 或健康原文。
5. packet 的引用顺序稳定，包含内部映射；Manifest 不含 `contextRef` 与本地 ID。
6. 运行只新增 `CONTEXT_READY` 审计行，不写任何日程实体。
