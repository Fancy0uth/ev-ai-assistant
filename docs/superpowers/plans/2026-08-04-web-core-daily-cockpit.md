# Web Core Daily Cockpit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a production-shaped Web core in which a signed-in user can safely manage projects, tasks and in-app schedule blocks, then see an explainable daily status dashboard.

**Architecture:** Create `apps/web` as a standalone Next.js App Router application beside the preserved static Demo. Supabase Auth and Postgres own cloud account and core data; the browser uses the publishable key under RLS, while server rendering uses the documented SSR client. Domain calculations are pure TypeScript and receive already-authorized data. No Bridge, calendar import, GitHub or model API is introduced by this plan.

**Tech Stack:** Node.js >= 20.9, current stable Next.js App Router, React, TypeScript, Tailwind generated by `create-next-app`, Supabase CLI + Postgres, `@supabase/ssr`, Zod, Vitest, Playwright.

## Global Constraints

- Keep the existing root static Demo unchanged; production work is under `apps/web`.
- Use only current stable versions selected by `create-next-app` and pin them in `apps/web/package-lock.json`.
- Use Supabase Auth cookies through `@supabase/ssr`; never expose a service-role key in `apps/web`.
- Enable RLS on every user-data table, then prove cross-user reads and writes are denied.
- Persist only core cloud data: profiles, projects, tasks and schedule blocks. Never add API keys, Agent memory or chat content.
- All mutable Task and ScheduleBlock operations include a numeric `version` and reject stale writes with `409 CONFLICT`.
- User-visible copy is Simplified Chinese; interactive controls have accessible names and keyboard focus.
- A task is not complete until its focused tests, `npm run lint`, `npm run test`, and `npm run build` pass in `apps/web`.

- [ ] **Step 3: Implement server-owned CRUD and optimistic update condition**

```ts
const { data, error } = await supabase
  .from('tasks')
  .update({ status: input.status, version: input.version + 1 })
  .eq('id', id)
  .eq('version', input.version)
```

- [ ] **Step 3: Implement the transparent scoring contract**

```ts
export type DailyStatusLevel = 'STEADY' | 'TIGHT' | 'OVERLOADED';

export function calculateDailyStatus(input: DailyStatusInput): DailyStatus {
  const overload = Math.max(0, input.scheduledMinutes - input.availableMinutes);
  const score = Math.max(0, Math.min(100,
    70 + Math.round(input.yesterdayTaskCompletion * 15)
      + Math.round(input.yesterdayLearningCompletion * 10)
      - Math.min(30, Math.ceil(overload / 15))
      - Math.min(20, input.openTasks.filter((task) => task.priority === 3).length * 4),
  ));
  // Build reasons and up to three priorities only from the supplied input.
}
```

Keep the formula, thresholds and reasons in the domain file so UI copy cannot hide why a score changed. The page loads only the signed-in user's data and handles the empty-day state explicitly.
