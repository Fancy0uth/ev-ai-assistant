# v0.4 Action Scheduling Foundation 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实施。每项先 RED、再 GREEN、再重构、聚焦验证和原子提交。

**Goal:** 让真实 UI Task/Action 形成有审计生命周期的 TimeRequest，经调用前语义预检、Provider 建议和 Owner 确认回到 Today；补齐手工 Event Proposal 与真实 ID 详情路由。

**Architecture:** `TaskSchedulingUnitOfWork` 只在本地 SQLite transaction 中协调 TaskRepository 与 CalendarRepository；Repository 保持单模块 SQL。TimeRequest 使用 additive `ACTIVE/CLOSED` 生命周期，Daily Planning 只读取 ACTIVE；preflight 持久化、批准和 claim 使用短事务，DPAPI/Provider 网络调用始终在事务之外。

**Tech Stack:** TypeScript、Zod、Fastify、better-sqlite3、React/Next.js、Vitest、Node test runner、Playwright。

**Spec:** [v0.4–v0.9 绑定设计](../specs/2026-08-23-v0.4-v0.9-mvp-design.md) · [总路线](2026-08-23-v0.4-v0.9-mvp-roadmap.md) · 实现基线 `a2a21a8`

## Global Constraints

- 只做 additive migration；旧 Owner/Task/Run/TimeRequest/Proposal 不删除、不重写。
- `CreateTaskInput.scheduling` 可省略；`UpdateTaskInput.scheduling === undefined` 表示保持，`null` 表示取消排程，旧客户端无需改变。
- Task 变为 DONE 时关闭活跃 TimeRequest；OPEN Task 明确取消排程时也关闭；历史行保留，重新排程创建新的 ACTIVE 行。
- 所有 Provider 外发语义先经 Owner preflight；07:00 无已批准语义时只建本地 preflight。
- Fake 仅在现有 test-only 三重闸门中；生产未配置 Provider fail closed。Core 仍只监听 `127.0.0.1`。
- 每项只写列出的文件；每项 GREEN 后必须运行该项 typecheck，失败不得提交。

**接口与兼容：**

**允许/禁止：** 禁止改变既有 Task status 枚举、破坏性表重建、回填虚构排程或让 input 接受 ownerId/API key/prompt/path。

### V4-03 — 用本地 Unit of Work 原子同步 Task↔TimeRequest

**依赖：** V4-02。

**文件：** Create `apps/core/src/modules/tasks/task-scheduling-unit-of-work.ts`；Modify `apps/core/src/modules/tasks/repository.ts`、`apps/core/src/modules/tasks/service.ts`、`apps/core/src/modules/tasks/routes.ts`、`apps/core/src/app.ts`；Create `apps/core/tests/v0.4-task-scheduling-unit-of-work.test.ts`。

**装配与事务：** `app.ts` 只创建一次 taskRepository/calendarRepository，再以 `createTaskSchedulingUnitOfWork(database, { taskRepository, calendarRepository, newId, now })` 注入 TaskService。Unit of Work 用一个 `database.transaction` 调用两个 Repository；TaskRepository 只读写 `tasks`，CalendarRepository 只读写 `time_requests`。事务内禁止 credential、Provider、HTTP、文件或异步 callback。

**状态规则：** create 有 scheduling 才建 ACTIVE；普通 update 同步标题/优先级/日期/窗口且不重复；`status=DONE` 关闭为 COMPLETED；OPEN Task 的 `scheduling:null` 关闭为 CANCELLED；重新 OPEN/排程创建新 ACTIVE。增加 `GET /v1/tasks/:id`，跨 Owner 与不存在统一 404。

**允许/禁止：** 禁止把跨模块 SQL 放进 TaskRepository、嵌套独立 connection、在网络期间持有 transaction、删除旧 TimeRequest 或直接复制 Task 为 Action。
