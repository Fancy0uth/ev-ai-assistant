# v0.4 Action Scheduling Foundation 实施计划

**Goal:** 让真实 UI Task/Action 形成 TimeRequest，经调用前语义预检、Provider 建议和 Owner 确认回到 Today；补齐手工 Event Proposal 与真实 ID 详情路由。

**Binding:** [总设计](../specs/2026-08-23-v0.4-v0.9-mvp-design.md) · [总路线](2026-08-23-v0.4-v0.9-mvp-roadmap.md) · 基线 `a2a21a8`

## 版本边界

- 保留 `tasks`、`actions`、`time_requests` 和既有 Daily Plan；只做加法迁移，旧 Owner/Task/Run 不丢失。
- Task/TimeRequest、Proposal/Event 的相关写入必须各自在单一 SQLite transaction 内完成。
- 标题、领域、截止日期等新增语义必须先由 Owner 在 preflight 中查看/编辑/批准；无既有批准策略时，07:00 只建本地 preflight，不调用 Provider。
- Fake 仅在现有 test-only 三重闸门中使用；生产未配置 Provider 必须 fail closed。
- Core 仍只监听 `127.0.0.1`；本版不安装依赖、不调用真实 Provider、不发布。

### V4-02 — 原子实现 Task/Action → TimeRequest 与语义 preflight

**依赖：** V4-01。

**文件：** `apps/core/src/modules/tasks/repository.ts`、`apps/core/src/modules/tasks/service.ts`、`apps/core/src/modules/daily-planning/preflight-service.ts`、`apps/core/src/modules/daily-planning/context-service.ts`、`apps/core/tests/v0.4-planning-input.test.ts`。

**契约/API：** Task create/update 在同一 transaction upsert origin-linked TimeRequest；完成/取消只关闭排程输入，不删除历史。`prepare/approve/consumePreflight` 校验 owner、版本和 base schedule version；Provider 只收到已批准的 safeTitle/domain/deadline 与匿名排程字段。

**允许/禁止：** 只写 Task bridge 和 preflight service；禁止复制 Task 为 Action、删除已应用 Event、把本地实体 ID/ownerId/健康原文/项目正文发送给 Provider、在数据库事务中等待网络。

- **RED:** 在聚合测试中覆盖 UI 形状的 Task create 同时生成一个 TimeRequest、失败全回滚、更新不重复、完成后不再进入 context；覆盖未批准/跨 Owner/stale preflight 被拒绝且 Provider call count 为零。运行 `npm test --workspace @ev/core -- tests/v0.4-planning-input.test.ts`，预期失败。
- **GREEN:** 实现 origin upsert 与 preflight 状态机；运行同一命令通过。
- **重构/提交:** 运行 `npm run typecheck --workspace @ev/core`、聚焦 lint、`git diff --check`；提交 `feat(core): bridge tasks into approved planning context`。

**验收：** 生产 Task API 成为真实计划输入来源，且 Provider 无法绕过 Owner-approved preflight。
