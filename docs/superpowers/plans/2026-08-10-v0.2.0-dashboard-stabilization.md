# EV AI Dashboard v0.2.0 Dashboard 稳定化实施计划

> 本计划执行 `2026-08-10-v0.2.0-improvement-design.md`。每个编码任务由新的 `gpt-5.6-terra`（`reasoning_effort=xhigh`、默认服务速度）在隔离 fork 中按 TDD 实现；随后由新的 `gpt-5.6-sol`（`reasoning_effort=xhigh`、`service_tier=priority`）只读复审。主 Agent 冻结契约、集成提交、运行全套门禁并处理审查分类。

## 1. 执行规则

- 基线：`v0.1.0` / `83f4b37`；实现分支：`codex/v0.2.0`。
- 结构性编码前后分别运行 Code Intel Sentrux `session_start` / `session_end`。
- 每个任务遵循：上下文包 → RED 测试 → 确认按预期失败 → GREEN 最小实现 → 聚焦验证 → Terra 自审 → 独立提交 → Sol 新上下文反方审查 → 同一 Terra 修正 → Sol 复审。
- 不并行运行实现 Agent；相邻任务可以读前序提交，但不得改写其他 Agent 的未提交工作。
- 每个任务候选写入范围约不超过五个文件。若实现证明必须扩张，先由主 Agent拆成更小任务，不能把重构夹带进当前提交。
- 不修改 migration 001，不更新 Code Intel baseline 隐藏回归，不读取或清理用户现有数据目录。
- 所有 API 错误保持 `{ error: { code, message, details? } }`；新增接口全部在 `/v1` 下并由共享 Zod 契约验证。
- 下列命令中的 workspace 聚焦测试先通过，任务才允许提交；最终仍需运行全仓门禁。

## 4. 每个任务的 Sol 复审清单

Sol 必须在新上下文中按以下顺序分类，而不是只给总体评价：

1. 契约误读：实现与冻结规格冲突；退回 Terra 修正。
2. 需修复：有效 P0/P1、安全、数据、Owner 隔离、回归或测试证据问题；退回 Terra 修正。
3. 接受的权衡：符合已写入规格的最小实现限制；记录但不扩张。
4. 噪声：无法复现、与范围无关或要求被明确拒绝的建议；写明拒绝理由。

复审重点：生产无 Fake Provider、503 前零写入、migration 001 未变、BFF 只连 loopback/只转发 `ev_session`、Task 409 保留最新实体、E2E 不碰用户数据。
