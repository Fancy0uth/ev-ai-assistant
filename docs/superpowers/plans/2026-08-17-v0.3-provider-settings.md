# V3-03b Provider Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让已登录的唯一 Owner 能在浏览器安全配置、替换、删除及主动测试 DeepSeek API Key，同时页面只显示非敏感状态。

**Architecture:** Core 继续是唯一可解密/调用 Provider 的进程。`ProviderCredentialService` 已在 V3-02/V3-03a 完成 DPAPI 存储与测试结果持久化；本计划只在 Fastify 组合根把它接入受认证路由，并由 Next.js BFF 代理到已有的本机 Core。Web 保存 Key 后立即清空浏览器内存中的输入值，随后仅从 metadata 渲染状态。

**Tech Stack:** TypeScript 6、Fastify 5、Zod 4、SQLite、React 19、Next.js 16、Vitest、Testing Library。

## Global Constraints

- 只允许单 Owner 和本机 Core；每个新端点都使用现有 `createAuthGuard`。
- API Key 绝不进入 Git、`.env`、browser storage、日志、公开响应、Agent Memory、SQLite 明文或测试输出。
- 自动化测试只能注入 Fake SecretStore/Fake DeepSeek tester；不得调用真实 Provider。
- 保持 V3-01 的严格 Zod 输入/输出契约和现有 `/v1/providers`、Agent Run 契约不变。
- `PUT` 保存不自动调用模型；只有 `POST` 主动连接测试调用 Provider。模型失败以 200 metadata 内的 `lastConnectionTest: FAILED` 表达，不伪造成功。
- 删除必须要求 `{ confirmation: 'DELETE' }`；界面以第二个显式确认按钮触发。
- 不新增日计划、聊天、OCR、RAG、项目扫描、外部同步或任何 Agent 写入能力。

### Task 1: Core Provider Credential API

**Files:**
- Modify: `apps/core/src/app.ts`
- Modify: `apps/core/src/modules/providers/routes.ts`
- Create: `apps/core/tests/provider-credential-routes.test.ts`

**Interfaces:**
- Consumes: `createProviderCredentialService(database, secretStore, { connectionTester })`, `createWindowsDpapiSecretStore()`, `deepSeekCredentialWriteInputSchema`, `deepSeekCredentialDeleteInputSchema`, `deepSeekCredentialStatusResponseSchema`, and existing `authenticatedOwnerId`.
- Produces:
  - `GET /v1/providers/deepseek/credential` → `200 { data: DeepSeekCredentialMetadata }`
  - `PUT /v1/providers/deepseek/credential` with strict `{ apiKey }` → `200 { data: DeepSeekCredentialMetadata }`
  - `DELETE /v1/providers/deepseek/credential` with strict `{ confirmation: 'DELETE' }` → `200 { data: DeepSeekCredentialMetadata }`
  - `POST /v1/providers/deepseek/connection-test` → `200 { data: DeepSeekCredentialMetadata }`
  - `401` for all unauthenticated calls; `422` for invalid bodies; `409 CREDENTIAL_NOT_CONFIGURED` for a test without a Key; `503 SECRET_STORE_UNAVAILABLE` for unavailable DPAPI.

- [ ] **Step 1: Write the failing Core route tests**

  In `provider-credential-routes.test.ts`, build the app with a fake opaque `SecretStorePort` and injected `DeepSeekConnectionTester`. Prove all four unauthenticated requests return 401; a logged-in Owner sees `NOT_CONFIGURED`; strict bodies reject extra/missing fields with 422; PUT returns `CONFIGURED` without Key/ciphertext/suffix; POST records both `SUCCEEDED` and `FAILED/RATE_LIMITED` fake results; DELETE only accepts `DELETE` and returns `NOT_CONFIGURED`; an unconfigured POST is 409; a failing SecretStore save is 503. Assert every serialized response omits both test key and opaque stored token.

- [ ] **Step 2: Run the route test and verify RED**

  Run: `npm run test --workspace @ev/core -- tests/provider-credential-routes.test.ts`

  Expected: FAIL because the credential routes and App composition do not yet exist.

- [ ] **Step 3: Compose the service and register typed routes**

  In `app.ts`, add optional test seams `secretStore?: SecretStorePort` and `deepSeekConnectionTester?: DeepSeekConnectionTester`; instantiate the production default with `createWindowsDpapiSecretStore()`, then create one `ProviderCredentialService` and pass it to `registerProviderRoutes`. In `routes.ts`, add the four guarded routes, parse the two request bodies at the boundary, return `deepSeekCredentialStatusResponseSchema`, and translate only `CredentialNotConfiguredError`/`SecretStoreUnavailableError` to the codes above. Do not catch/log a raw API Key or attach it to `ApiError` details.

- [ ] **Step 4: Run Core tests and verify GREEN**

  Run: `npm run test --workspace @ev/core -- tests/provider-credential-routes.test.ts tests/deepseek-connection.test.ts tests/provider-credential-service.test.ts && npm run typecheck --workspace @ev/core`

  Expected: PASS; test output contains no real credentials and no network call occurs.

- [ ] **Step 5: Commit the Core API slice**

