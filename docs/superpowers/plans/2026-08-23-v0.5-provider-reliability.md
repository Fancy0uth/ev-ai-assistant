# v0.5 Provider Reliability 实施计划

**Goal:** 建立真实 DeepSeek/DPAPI 人工验收通路，并为所有模型调用提供幂等、恢复、超时、配额、脱敏持久日志和一致版本元数据。

**Binding:** [总设计](../specs/2026-08-23-v0.4-v0.9-mvp-design.md) · [总路线](2026-08-23-v0.4-v0.9-mvp-roadmap.md) · 入口为 v0.4 PASS commit

## 版本边界

- 真实 Provider 未配置、Key 解密失败、超时或超配额都 fail closed；不得回退 Fake 或样例成功。
- Key 只经 Owner UI → Core → DPAPI；不进入 SQLite、日志、错误、命令行、review 或 Git。
- `Idempotency-Key` 绑定 Owner、操作、规范化请求哈希；冲突不重用，重复不重复计费/写 Proposal。
- Prompt、Provider 输出和远端错误均是不可信数据；日志只保存白名单元数据和脱敏摘要。

### V5-02 — 端到端实现 Idempotency-Key

**依赖：** V5-01。

**文件：** `apps/core/src/modules/daily-planning/service.ts`、`apps/core/src/routes/daily-planning.ts`、`apps/web/src/app/api/core/[...path]/route.ts`、`apps/core/tests/daily-planning-routes.test.ts`、`apps/web/tests/daily-plan-workspace.test.tsx`。

**API：** 所有会创建 Provider Run/Proposal 的 POST 要求 UUID `Idempotency-Key`；BFF 精确转发该 header。首次请求锁定规范化 hash；完成后重放相同 status/body；处理中返回稳定 409/Retry-After；同 key 异 body 返回 `IDEMPOTENCY_CONFLICT`。

**允许/禁止：** 只写 Daily Plan 首条幂等链和 BFF allowlist；禁止转发任意客户端 header、跨 Owner 重用、失败后默默新建 Run。

- **RED:** API/BFF 测试覆盖缺 header、并发双击、完成重放、hash 冲突和 Owner 隔离；运行 `npm test --workspace @ev/core -- tests/daily-planning-routes.test.ts` 与 `npm test --workspace @ev/web -- tests/daily-plan-workspace.test.tsx`，预期失败。
- **GREEN:** 用短事务 claim/complete idempotency record，并只转发白名单 header；同一命令通过。
- **重构/提交:** Core/Web typecheck、聚焦 lint；提交 `feat(provider): enforce idempotent generation requests`。

**验收：** 网络重试与双击只产生一次真实调用和一个 Proposal。

### V5-03 — 实现陈旧 Run 恢复、超时与本地配额

**依赖：** V5-02。

**文件：** `apps/core/src/modules/daily-planning/provider.ts`、`apps/core/src/modules/daily-planning/deepseek-provider.ts`、`apps/core/src/modules/daily-planning/service.ts`、`apps/core/src/modules/daily-planning/automation-service.ts`、`apps/core/tests/daily-planning-service.test.ts`。

**运行规则：** Core 在网络前占用带过期时间的 lease；启动和下一次请求时把超期 RUNNING 标为 `INTERRUPTED` 后按同 idempotency record 至多恢复一次。连接/首字节/总时限和 Owner 每日 calls/tokens 上限由本地 policy 控制，超限在调用前拒绝。

**允许/禁止：** 只写 Provider/Daily Plan 运行包络；禁止无限 retry、在 SQLite transaction 中发网络请求、用前端计数作为配额事实、把 timeout 当成功。

- **RED:** 在 service 测试中用 fake clock/abortable adapter 覆盖 crash lease、单次恢复、超时 abort、配额边界和重入；运行 `npm test --workspace @ev/core -- tests/daily-planning-service.test.ts`，预期失败。
- **GREEN:** 实现 lease/abort/quota reservation 与确定性终态；同一命令通过。
- **重构/提交:** Core typecheck、聚焦 lint；提交 `feat(provider): recover stale runs within bounded policy`。

**验收：** 所有 Run 最终可解释地完成/失败/中断，不存在永久 RUNNING 或无界调用。
