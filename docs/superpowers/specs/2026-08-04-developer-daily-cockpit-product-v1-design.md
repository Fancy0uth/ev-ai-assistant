# 开发者每日驾驶舱：产品 v1 设计规格

## 1. 目标

为独立开发者提供一个 Web 优先的每日驾驶舱：打开首页后，用户能先回答“我今天状态怎么样、下一步最该做什么”，再管理工作、学习和生活任务。

成功不是堆叠待办功能，而是让用户在 30 秒内看清今日负荷、昨天的执行情况和一条可执行的下一步；在同意后，由 AI 把任务、日程与本地累积记忆整理成建议。

### 目标用户

有代码、Issue、PR、学习任务，同时需要兼顾饮食、运动和日常事务的个人开发者。首版不处理团队协作、多人分派、企业权限或自动执行外部操作。

## 2. 已确认的产品边界

### v1 必做

- 真实账号登录与云端同步：任务、项目、应用内日程块和设置。
- 首页每日状态：今日任务/日程负荷、昨日任务完成度、昨日学习完成度，输出分数、状态、原因和行动建议。
- 任务与项目：创建、编辑、完成、推迟、优先级、工作/学习/生活分类、学习任务标记。
- 应用内日程：日/周时间轴，可把任务安排到时间块。
- 日历：用户本地选择并导入 `.ics` 快照；无持续 Apple 同步或写回。
- GitHub：用户手动刷新、只读读取选定范围的 Issue/PR；可显式转换为应用内任务。
- AI：可选安装本地 Agent Bridge；未安装仍可完整使用非 AI 功能。
- 本地累积记忆：Bridge 保留 API Key 和记忆，云端绝不持久化二者。

### v1 不做

- 原生 iOS/Android、Apple Calendar 自动双向同步、跨设备 Agent 记忆同步。
- GitHub、日历、邮件或任何第三方写操作。
- 浏览器自动化、文件/终端访问、Shell、邮件或通用自治 Agent。
- 团队协作、社交功能、健康医疗建议或后台自动替用户执行任务。

## 3. 体验与功能设计

### 3.1 首页：每日驾驶舱

首页固定以“今天状态”为首屏，按下列输入产生可解释结果：

1. 今日未完成任务数量、优先级和已排程负荷；
2. 昨日任务完成率；
3. 昨日学习任务完成率；
4. 今天剩余可用时间与冲突日程。

状态输出包含分数（0–100）、等级、变化趋势、三条影响原因、最多三件今日重点，以及一条建议。分数是透明的启发式指标，不假装是健康诊断。

### 3.2 核心对象

| 对象 | 关键字段 / 行为 |
|---|---|
| Task | 标题、分类、项目、优先级、状态、学习标记、截止时间、日程时间、版本号 |
| Project | 名称、状态、目标日期、归属任务 |
| ScheduleBlock | 起止时间、时区、来源、关联任务、冲突状态 |
| GitHubSnapshot | 仓库和外部不可变 ID、刷新时间、状态、快照内容 |
| AgentProposal | 输入版本、建议、建议的内置变更、到期时间、确认状态 |
| MemoryCard | 内容、来源摘要、置信度、标签、版本、过期策略、是否固定 |

任务的完成与推迟必须更新每日状态的计算输入。每个可由 Agent 产生的任务或日程变更均先生成 `AgentProposal`，由用户预览并逐项确认后才执行。

### 3.3 日历与 GitHub

`.ics` 导入是明确的快照导入：使用 UID、RECURRENCE-ID、时区与来源文件标识进行确定性更新；支持取消事件和重复导入，不产生隐性重复。首版对重复事件设置可见的展开窗口，并显示“导入成功 / 部分成功 / 失败”及具体原因。

GitHub 刷新显示最近成功时间、覆盖页数、部分失败、限流和陈旧数据状态。转换任务保留 `provider + account + repositoryId + itemType + immutableItemId`，并以唯一约束去重；转换不会改写 GitHub。

### 3.4 本地 Agent Bridge 与记忆

Bridge 是用户主动安装的跨平台本地伴随程序。它只绑定 loopback 地址，并使用安装级身份、严格来源白名单、短时确认令牌和防重放机制接收请求。公开 HTTPS Web 端必须处理浏览器的 CORS / Private Network Access 预检；这是一条发布前端到端验收项。

调用 AI 时，网页先展示精确的待发送上下文、目标模型/供应商、以及第三方数据保留提示。用户确认后，Bridge 才检索本地记忆并直接向模型供应商发送该次请求。云端不会接收 API Key、记忆内容、原始 Agent 对话或检索结果。

记忆在本地 SQLite 中分层保存：

1. 近期结构化事件缓冲；
2. 周度或项目摘要；
3. 轻量的长期 Memory Card（偏好、已验证习惯和稳定项目事实）；
4. 用户固定的记忆。

不默认保留完整对话。所有卡片记录来源、版本与派生关系；重复合并、摘要、过期、导入和删除须原子执行。删除源记忆会级联删除或重新生成依赖摘要。记忆按实际 UTF-8 字节和索引开销计量：20 MB 时提示整理，50 MB 时拒绝会使总量继续增长的写入；固定记忆不自动删除。

## 4. 推荐架构

```
浏览器 Web（Next.js + TypeScript）
  ├─ Supabase Auth / Postgres / RLS：账号与核心业务数据
  ├─ GitHub OAuth / 只读刷新：GitHub 快照
  └─ localhost Bridge 协议：用户确认的 AI 请求
                                 │
本地 Agent Bridge（桌面伴随程序） ── SQLite 记忆 + OS 凭据库 API Key
                                 │
                           用户选择的模型 API
```

推荐采用单仓库、两个可部署单元：`apps/web` 是 Web 应用，`apps/agent-bridge` 是本地 Bridge，`packages/contracts` 保存两者共享的版本化 schema。生产重构前会保留当前静态 Demo 作为交互参考；移动端是后续独立项目，而非本次架构的隐性承诺。

云端仅保存用户可在网页管理的业务数据。每张用户数据表启用并测试以不可变 `auth.uid()` 为边界的 RLS；后台任务、导出及对象存储路径也必须遵从同一租户边界。

## 5. 接口与一致性规则

- 所有外部输入（表单、`.ics`、GitHub 响应、Bridge 请求）在边界使用 schema 校验；错误统一为机器码、用户消息和可选诊断详情。
- 列表接口必须分页；更新使用 `PATCH` 语义。
- Task、ScheduleBlock 与 AgentProposal 都有版本字段。执行建议时必须以乐观并发控制原子校验版本；不一致返回冲突预览，禁止静默覆盖。
- Bridge 协议版本化，网页与 Bridge 不兼容时明确提示升级或降级，不回退到不安全调用。
- 本地 Bridge 不执行外部副作用；其唯一功能是记忆管理、模型请求与返回建议。

## 6. 建议技术栈与命令

生产工程尚未初始化，因此不预先写死可能过期的框架小版本。首个实施任务会依据官方文档选择并锁定当时稳定的 Next.js、React、TypeScript、Supabase CLI 与 Bridge 运行时版本，再写入 lockfile。

计划中的标准命令为：

```text
npm run dev                 # 启动 Web 开发环境
npm run test                # 单元与组件测试
npm run test:e2e            # Playwright 端到端测试
npm run lint                # 静态检查
npm run build               # Web 生产构建
npm run bridge:dev          # 启动本地 Bridge 开发环境
supabase db reset           # 本地数据库和迁移验证
```

## 7. 失败状态与验收

| 边界 | 必须可见的失败状态 |
|---|---|
| 登录 / 云端 | 会话失效、无权限、离线、保存冲突、恢复动作 |
| GitHub | 未授权、限流、分页失败、部分刷新、数据陈旧 |
| `.ics` | 格式错误、时区/重复规则错误、部分导入、可重试 |
| Bridge | 未安装、版本不兼容、来源不被允许、确认超时、Bridge 离线 |
| 模型 API | Key 无效、网络失败、供应商限流、超时、响应校验失败 |
| 记忆 | 存储接近/达到上限、导入失败、删除影响预览、恢复失败 |
| 建议应用 | 建议过期、实体已变更、部分冲突、用户取消 |

发布前最低自动化验证：RLS 跨用户拒绝测试、数据库迁移测试、任务/日程 CRUD、版本冲突测试、`.ics` 时区和重导入 fixture、GitHub 分页/部分失败 fixture、Bridge 来源与令牌测试、记忆派生/删除/上限测试，以及主用户路径的浏览器端到端测试。

## 8. 工程边界

- **始终做：** 类型校验、可访问性、错误状态、迁移与 RLS 测试、提交前测试。
- **需先征求确认：** 新增第三方付费服务、数据库不可逆迁移、真实部署、修改认证供应商、引入新的模型供应商或遥测服务。
- **绝不做：** 提交密钥；把 API Key 或 Agent 记忆写入云端；无确认地应用 Agent 变更；赋予 v1 外部写入、Shell、文件或浏览器权限。

## 9. 成功标准

1. 新用户可注册、登录，并在另一浏览器会话看到同步的任务与日程。
2. 用户可在首页理解状态理由、完成或推迟任务，并看到结果更新。
3. `.ics` 重复导入不会产生重复日程，错误或部分成功可见且可恢复。
4. GitHub 刷新与转换任务可追溯、可去重，且不改写 GitHub。
5. 未安装 Bridge 的用户不会被阻塞；已安装用户可以预览并确认数据后得到建议。
6. API Key、全部 Agent 记忆及本地记忆检索结果均不会进入产品云端。
7. 任何建议变更在实体版本过期时不会覆盖用户最新编辑。
