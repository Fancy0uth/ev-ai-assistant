## 1. 目标与成功定义

本设计把已经批准但尚未完成的 MVP 拆成六个可连续交付的薄垂直版本。最终结果仍是同一个产品：单一 Owner 在自己的 Windows 电脑上运行 Web、Core、SQLite、记忆和 Agent Loop；桌面与私有 iPhone Safari 访问同一套 Web；所有高影响日程变化先形成 Proposal，再由 Owner 确认；项目集成始终只读。

完整成功链为：

```text
真实用户输入
  -> 本地、Owner 隔离的领域事实
  -> 可见且可编辑的最小外发上下文
  -> 真实 Provider 或明确的 fail-closed 状态
  -> schema + 确定性规则验证后的领域 Proposal / TimeRequest
  -> 唯一日程 Proposal
  -> Owner 确认
  -> Today 时间轴、详情页、反馈与本地记忆
  -> 可备份、可恢复、可诊断的 Windows 常驻运行
```

v0.9 完成时必须同时证明：批准 MVP 中项目、课程、健身、饮食、记忆和日程各有一条真实闭环；真实 Provider 未配置时没有 Fake 或样例成功；Core 未离开 loopback；物理 iPhone Safari 只通过认证的私有 HTTPS Web 边界访问；旧 Owner、Task、Run 和历史审计均保留。

## 2. 权威来源与冲突处理顺序

出现冲突时按下列顺序裁决，低位资料不能删除或缩小高位已批准目标，只能说明当前实现状态：

1. `docs/product/PRD.md` 与 `docs/product/MVP-SCOPE.md` 的批准产品目标、用户边界、确认边界和延期项；
2. 当前仍为 Accepted 的 ADR，且新 ADR 对其明确 supersede 的旧决定具有优先级；
3. `TECH_SPEC.md` 与 `ARCHITECTURE.md` 的目标契约；
4. `IMPLEMENTED-MVP-DESIGN.md`、测试和源码所证明的当前事实；
5. v0.3 Sol 审查对证据缺口的分类；
6. 本设计与六份实施计划对后续版本的实现顺序。

现行 ADR 解释如下：

- ADR-005 取代 ADR-001/002：不再使用产品云端数据库或本地 Bridge 分裂架构；Web + Core 均为 Owner 主机上的本地系统。
- ADR-007 取代 ADR-004：Apple 日历、学校网站、穿戴设备和 GitHub 云同步仍不进入 v0.4–v0.9。
- ADR-010 取代 ADR-006 的项目写入/Implement Runner：Provider 分域路由仍可用，但项目分析永远只有过滤快照，无代码、Shell 或 Git 写入能力。
- ADR-009/012/013 继续约束 Proposal、DPAPI、07:00 日计划和失败状态。

## 4. `a2a21a8` 当前实现事实

### 4.1 可复用底座

- npm workspace：`apps/core`、`apps/web`、`packages/contracts`、`packages/domain`；Node 24、TypeScript 6、Fastify 5、Next.js 16、React 19、SQLite/better-sqlite3。
- SQLite 迁移到 v16，具备 Owner、session、Task、Event、Action、Signal、TimeRequest、通用 Proposal、课程导入 Run、Agent Run、四个记忆 scope、餐食、课程资料、项目 scope、DPAPI credential、Daily Plan Run/Proposal/Decision。
- Core 配置拒绝任何非 `127.0.0.1` 的 `EV_CORE_HOST`；Web BFF 也只接受 loopback Core origin。
- Owner 会话使用 HttpOnly、SameSite=Strict Cookie；生产配置启用 Secure；登录/初始化有限流。
- Daily Plan Provider 是真实 DeepSeek HTTP adapter；密钥由 DPAPI CurrentUser 保护；未配置/无效响应 fail closed。
- Proposal 确认、schedule version、Daily Plan 部分采用、迁移保留、Owner 隔离和 test-only Fake 已有自动化保护。

### 4.2 不能误称为已交付的能力

| 能力 | 当前事实 |
| --- | --- |
| Task/Action 参与排程 | Task 只写 `tasks`；生产代码不调用 `createTimeRequest()`；E2E 直接插入 TimeRequest |
| 语义日计划 | Provider 只收到 `contextRef`、时长、优先级、可用窗口和恢复枚举，无标题、领域、截止语义 |
| 外发预检 | Context Manifest 在 Provider 调用后才能从 Proposal explanation 查看 |

| OCR/视觉 | 只有可注入 Port；生产无 adapter；输入以 Base64 进入服务，未落私有 artifact 文件；低置信候选不能编辑后继续 |

## 5. 全局不可变边界

### 5.1 身份、数据与机密

- 单一 Owner。所有业务表、run、artifact、记忆、日志索引和幂等记录均带 `owner_id`，查询以 Owner 为首要条件。
- 所有用户数据、记忆、artifact、运行日志和备份保留在 `<EV_DATA_DIR>`；不建立产品云同步。
- Provider Key 不提交、不写日志、不进入网页、prompt、API 响应或测试 fixture。Windows 使用 DPAPI CurrentUser；其他系统只有等价 OS Secret Store 可用时才启用生产密钥持久化。
- 测试 Fake 只可在 `NODE_ENV=test`、显式测试 flag 和 runner-owned 临时数据目录同时成立时装配；生产构建无法选择 Fake。

### 5.2 网络与副作用

- Core 默认且生产均只监听 `127.0.0.1`；不得提供关闭这一限制的配置开关。
- iPhone 只连接经认证的私有 HTTPS Web 网关/隧道；网关只反代 Web loopback，绝不反代 `4311`、SQLite、artifact、记忆目录或 local-admin API。
- 外部写入和高影响动作必须 Proposal + Confirm。日程新增/改期/取消、训练安排、学习/项目时间请求和确认餐食均有版本、幂等、审计。
- 项目集成只读。不能写代码、文件、Git index、branch、commit、push、merge、release；不能向项目 Provider提供原路径或可写工具。

### 5.3 数据演进

- 只做版本化加法迁移：新增表、列、索引、trigger 或兼容视图；不删除/重命名旧表和列，不清洗历史行。
- 每次迁移测试从冻结的 v1、v2、v16 数据库升级，并核对 Owner、Task、Agent conversation、Run 和 Proposal 计数/ID。
- 需要改变旧 CHECK 枚举时优先使用 companion table/新版本表，不通过未审计的表重建丢失历史。
- 恢复操作先创建新的可验证备份；校验失败停止并保留原数据。

### 5.4 不可信数据

Prompt、模型输出、网页/PDF、OCR、课程资料、营养 Provider 响应、动作资料、Memory 文本、项目文件和 Git 元数据全部是不可信数据，不是指令。它们必须经过大小限制、schema、来源、领域规则和输出编码；任何文字都不能提升 capability、调用 SQL/Shell、选择文件路径或绕过确认。

## 6. 目标模块与契约

```text
Web real routes
  -> same-origin BFF (path/header/origin allowlist)
      -> Core loopback
          -> Owner guard + Zod boundary
          -> application service + idempotency + transaction
          -> deterministic domain rules
          -> SQLite repositories / local artifact & memory files
          -> capability-scoped Provider ports
          -> redacted audit/runtime event sinks
```

### 6.1 输入到排程

`Task` 和领域 `Action` 保留各自对象，但创建或显式“加入计划”时在同一事务中 upsert 一个来源关联的 `TimeRequest`：

```ts
interface TimeRequestOrigin {
  kind: 'TASK' | 'ACTION' | 'LEARNING_PLAN' | 'WORKOUT' | 'PROJECT_BRIEF';
  entityId: string;
  entityVersion: number;
}

interface SchedulingSemantics {
  safeTitle: string;
  domain: 'WORK' | 'STUDY' | 'FITNESS' | 'NUTRITION' | 'LIFE';
  deadlineLocalDate: string | null;
  durationMinutes: number;
  priority: 'LOW' | 'MEDIUM' | 'HIGH';
  availability: { earliest: string | null; latest: string | null };
}
```

唯一索引 `(owner_id, origin_kind, origin_id)` 防止重复 TimeRequest；来源实体更新/完成/取消时同步版本或关闭请求，不删除历史 decision。Daily Plan preflight 返回安全化语义和字段清单，Owner 可删改外发标题，但不能篡改本地 ID、时长约束或日程版本。Provider 只看 opaque `contextRef` 和已批准语义；Core 保留映射并进行确定性验证。

### 6.2 Provider Run

所有真实 Provider 共用以下运行包络：

```ts
interface ProviderExecutionPolicy {
  timeoutMs: number;
  maxInputChars: number;
  maxOutputChars: number;
  maxCallsPerRun: number;
  dailyCallLimit: number;
}

interface RedactedProviderCallRecord {
  runId: string;
  ownerIdHash: string;
  providerKey: string;
  capability: string;
  model: string;
  appVersion: string;
  contractVersion: string;
  durationMs: number;
  inputChars: number;
  outputChars: number;
  tokenUsage: { input: number | null; output: number | null };
  outcome: 'SUCCEEDED' | 'FAILED' | 'BLOCKED';
  failureCode: string | null;
}
```

记录不含 Key、请求/响应正文、完整 prompt、原始健康文本、网页内容或项目文件。超时、配额、无凭据、schema 失败均为可识别终态；没有任何“降级成样例成功”。

### 6.3 课程与资料

- 私有 artifact service 验证图片 MIME、魔数、像素/字节上限和 SHA-256，以随机文件名写入非静态目录。
- Vision Provider 只收到用户选中的 artifact、学期锚点和严格 extraction schema。
- 低置信候选形成可编辑 revision；只有全部必填字段通过本地周次/时间验证后才能创建 Course Import Proposal。
- Public Search Provider 只执行普通公开检索；结果保存 URL、标题、capturedAt、hash、provider/source kind。服务端 fetch 仅 HTTPS、禁止 redirect、loopback/private/reserved 地址、受保护学校登录和任意凭据。
- Learning Proposal 确认后创建课程 Action 与 TimeRequest，不直接写 Event。

### 6.4 健身与饮食

- 动作目录是带 catalog/version/license/source 的结构化事实；第一版检索使用 SQLite FTS/确定性过滤，RAG 只把检索到的动作说明作为引用交给 Provider。
- Check-in 原始事实本地保存；确定性规则先产 Signal；自由文本只有 Owner 选择后才进入外发 context。任何诊断、处方或紧急判断被 schema 和 UI 文案拒绝。
- Workout Proposal 确认后创建 Workout Session + TimeRequest；完成/感受/不适作为本地反馈，后续建议引用来源。
- 自然语言餐食先由模型解析候选名称/份量，再由获批的 NutritionDataProvider 返回数值和来源版本；Core 计算总量；Owner 编辑/确认后才写 meal record。LLM/RAG 数值不能落库。

### 6.5 项目、记忆与协调

- 本机 `evctl project authorize <path>` 是项目根唯一授权入口；远程 Web 只能列出、读取和触发已授权 scope。
- Snapshot Builder 使用 allowlist、数量/大小上限、secret pattern 排除和 no-optional-locks Git 读取。Provider 只收到过滤快照，不收到原路径或工具。
- Project Brief 包含阶段、证据、风险、下一 Action、估时和 TimeRequest；确认只写本应用。
- 记忆按 Owner + domain + entity scope 隔离，保存 observation、source、sensitivity、revision、容量和压缩 lineage；压缩生成新 revision，不覆盖 L0；用户可审查、编辑、软删除、恢复。
- 日程协调器只读取开放 TimeRequest 和最小 Signal，并通过 `(owner_id, local_date)` 协调 slot 产出一个活跃 Proposal。领域 Agent 永远不直接创建 Event。

### 6.6 私有访问与运维

- Tailscale Serve 或等价私有认证 HTTPS 网关只映射 Web loopback。应用本身继续要求 Owner 登录，并对 mutation 校验 Origin/Sec-Fetch-Site、CSRF/会话和幂等键。
- Windows 当前用户下的受管启动器负责 Web/Core 启动、健康检查、有限重启和登录后自启动；注册/卸载系统任务是执行时单独批准的主机动作。
- 备份使用 SQLite 一致性 backup/checkpoint 机制，把数据库、artifact/memory manifest、应用/迁移版本写入不可变 manifest；restore 在 Core 停止状态下先验证 hash、`quick_check`、Owner/关键计数和版本兼容。
- 本地 JSONL 运行日志只写 allowlisted 字段，按大小/日期轮转并有保留上限；默认无远程遥测。

## 8. 测试与 Sol 最小冒烟策略

### 8.1 Terra 任务循环

每个任务都必须：

1. 先写一个能准确证明缺口的 RED 测试并运行，记录预期失败；
2. 写最小 GREEN 实现，运行同一聚焦测试；
3. 重构只限本任务文件，运行聚焦测试、涉及 workspace typecheck 和聚焦 lint；
4. 检查 `git diff --check` 和敏感模式；
5. 形成一个可独立回退的原子 commit。迁移和生成的 lockfile 可与其直接依赖任务同 commit，但必须在文件清单中单列。

单任务通常不超过五个产品/测试文件；文档、迁移和由 package manager 生成的 `package-lock.json` 单列说明。测试不得使用用户 `EV_DATA_DIR`。

### 8.2 聚焦命令约定

当前仓库可执行的聚焦命令为：

```powershell
npm test --workspace @ev/contracts -- tests/<file>.test.ts
npm test --workspace @ev/domain -- tests/<file>.test.ts
npm test --workspace @ev/core -- tests/<file>.test.ts
npm test --workspace @ev/web -- tests/<file>.test.tsx
npm run typecheck --workspace @ev/contracts
npm run typecheck --workspace @ev/domain
npm run typecheck --workspace @ev/core
npm run typecheck --workspace @ev/web
npx eslint <explicit changed files>
git diff --check
```

现有 `scripts/run-e2e.mjs` 不转发 Playwright 参数。v0.4 第一个测试基础任务必须把 `process.argv.slice(2)` 安全追加到 Playwright `test` 参数，并由 `tests/e2e-runner.test.mjs` 证明；之后统一用：

```powershell
npm run test:e2e -- e2e/<focused-spec>.spec.ts --project=<configured-project>
```

每版 Sol 最小冒烟只运行该版聚焦 tests、受影响 workspace typecheck、必要 Web build/startup health 和一个关键浏览器路径，不把全仓 E2E 当作每版默认动作。

### 8.3 v0.9 完整集成门禁

v0.9 在其最小冒烟之后额外运行一次完整门禁；它证明总体目标，不能替代 v0.4–v0.8 的逐版冒烟：

```powershell
npm test
npm run typecheck
npm run lint
npm run build
npm run test:e2e
npm audit --omit=dev --json
npm test --workspace @ev/core -- tests/database.test.ts tests/migrations.test.ts tests/backup-restore.test.ts
git diff --check
```

另外执行 startup/health smoke、从冻结 v1/v2/v16 和最新备份的迁移恢复矩阵、桌面 Chromium、移动 WebKit/触摸上下文与物理 iPhone Safari。浏览器 runtime 下载、依赖 audit 网络访问和物理设备/私有网关配置在执行时需主 Agent 单独审批。

## 9. 版本结束审查契约

每版完成后创建且只创建对应证据文件：

```text
docs/reviews/2026-08-23-v0.4-sol-smoke-review.md
docs/reviews/2026-08-23-v0.5-sol-smoke-review.md
docs/reviews/2026-08-23-v0.6-sol-smoke-review.md
docs/reviews/2026-08-23-v0.7-sol-smoke-review.md
docs/reviews/2026-08-23-v0.8-sol-smoke-review.md
docs/reviews/2026-08-23-v0.9-sol-smoke-review.md
```

每份必须包含：

1. 基线 commit 与目标 commit；工作树/分支和审查模型；
2. 本版范围与明确不在范围；
3. 每条执行命令、退出码、通过/失败计数和原始结果摘要；不得只写“通过”；
4. 关键浏览器路径、桌面/移动尺寸、URL/路由、截图或 trace 路径、console/page error、物理设备/网关信息（适用时）；
5. 真实 Provider 还是 test-only Fake、Provider/模型非敏感版本、是否获得外部调用审批；不得记录 Key、正文或个人数据；
6. 迁移前后 Owner/Task/Run/Proposal 计数与恢复证据；
7. 发现按 P0/P1/P2/P3 分类，写出证据、影响、决定；
8. 审查结论 `PASS`、`CONDITIONAL PASS` 或 `FAIL`，不得用总测试绿掩盖产品链缺口；
9. 下一版入口 commit、剩余风险和执行审批门。

任一 P0、未处置 P1、数据丢失、Provider 假成功、Core 非 loopback、项目写入或缺失关键浏览器路径均使该版 FAIL，不能继续把后续功能叠加到该基线。

## 10. 执行时单独审批门

下列内容可以出现在代码和计划中，但 Terra 不得自行执行外部或主机变更：

| 动作 | 何时审批 | 未获批行为 |
| --- | --- | --- |
| 选择/调用真实 DeepSeek、视觉、搜索、营养或本地 Codex Provider | adapter 实施前确认供应商边界；每次人工真实 smoke 前确认外部调用 | 保持 NOT_CONFIGURED/BLOCKED；只运行 test-only Fake 自动化 |
| 新增 npm/native 依赖或 Playwright browser runtime | 修改 manifest/安装前 | 停止该任务，不用未审计替代包 |
| 安装/登录 Tailscale、执行 Serve、开放/修改端口或防火墙 | v0.9 主机验收前 | 只提交配置验证/文档和 dry-run，不改变主机 |
| 注册/删除 Windows Task Scheduler/服务、自启动、ACL | v0.9 脚本验证后、真实安装前 | 只做 isolated/dry-run 测试 |
| restore 真实用户数据库或删除备份/日志 | 每次真实恢复/删除前 | 只在 runner-owned 临时目录演练 |
| push、发布、部署、共享日志/截图/审查证据 | 每次外部写入前 | 仅本地 commit，不 push、不发布、不共享 |

## 11. 明确非目标

- 多 Owner、团队协作、产品云数据库、云同步、公开 SaaS；
- Apple/Google/Outlook 日历、学校受保护网站登录或抓取、穿戴设备、通知推送、原生 iOS/Android；
- Agent 自动修改代码/Git、自动发布、长时间无人确认执行；
- 医疗诊断、处方、紧急判断；
- Docker 作为 v0.9 前置条件；
- 把 v0.9 标记为 1.0、对外稳定版或公开发布。

## 12. 设计完成判据

本设计只能在六份计划都满足下列条件时视为可执行：每项有前置依赖、精确文件范围、契约/迁移说明、RED/GREEN/重构/commit、禁止事项、验收标准和聚焦命令；每版有 Sol 最小冒烟和统一 review 路径；v0.9 有额外完整集成门禁；没有用 Fake、接口骨架或文档状态冒充真实产品能力。
